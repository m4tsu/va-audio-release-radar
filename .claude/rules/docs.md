# 文書の規則

## 読者は「リポジトリしか持っていない人」

git に入る文書とコメントは最終成果物である。書いた日の会話を知らない読者が、
リポジトリの中身だけでその文を検証できなければ書かない。

書く前に 3 つ確かめる。

1. 会話を知らない読者が、この文を検証できるか
2. コードで表現できないか。できるなら文書に書かず、コードをファイル名で指す
3. この文書を削除する条件を書けるか。書けない文書は作らない

## 何をどこに書くか

| 情報の種類 | 置き場所 | 書き方 |
|---|---|---|
| 何を作る / 作らない、対象、指標、データの扱いの方針 | `docs/product.md` | 現在形。100 行以内 |
| システムの境界、依存方向、実行トポロジ、コンポーネント間の契約、不変条件 | `docs/architecture.md` | 現在形。150 行以内。型・スキーマ・URL・値・セレクタを書かない |
| 境界か範囲を変えた決定の理由と、採らなかった代替案 | `docs/decisions/NNNN-<slug>.md` | 1 決定 1 ファイル。状況 / 決定 / 帰結 / 採らなかった案。本文 20 行以内。状態は `accepted` か `superseded` |
| 外部サイトの制約 (robots.txt の引用、使える URL の形、取れる項目、落とし穴) | `docs/stores/<store>.md` | 事実と最終確認日。見出しの構成は `docs/stores/README.md` |
| 日付つきの測定 | `docs/research/<topic>-<date>.md` | 書いたら数字を変えない。他の文書は数字を写さずリンクする |
| 作業の進め方の規則 | `CLAUDE.md`、`.claude/rules/*.md` | 規則 + 理由 1 行。前者は常時、後者は該当パスを触ったときだけ読み込まれる |
| 型、スキーマ、値、アルゴリズム、URL の形、セレクタ、打ち切り条件 | コード | 文書に書かない |
| 1 モジュールに収まる機能の設計 | そのモジュール先頭のコメントとテスト | 文書を作らない |
| 定数・分岐の理由 | その行のコメント | 「なぜ」だけ。「何が起きたか」は書かない |
| 進行、担当、次の作業、ユーザーへの依頼、未決の提案、下書き | `work/` (git 管理外) | 形式自由。消す条件は下の「`work/` の寿命」 |
| 出来事の記録 (何が起きた、何回目、誰が) | コミットメッセージ | 文書とコメントに書かない |

同じ事実を 2 か所に書かない。出典を 1 つ決め、他はそこをファイル名で指す。

## `work/` の寿命

`work/` は形式自由だが、**消す条件の無いファイルを置かない**。git に入らないので、
古くなっても差分にも CI にも出ず、誰も気付かない。

| 置くもの | 消すとき |
|---|---|
| `work/status.md` | 消さない。書き足さずに上書きする。数字と状態には出どころと確認日を添える |
| `work/proposals/<topic>-<date>.md` | 決定が `docs/decisions/` に入るか、実装が main に入ったら消す |
| ユーザーへの依頼の下書き | 依頼を出したら消す |
| 実行の記録 (issue-batch の `<run>/` など) | その実行が終わったら消す。失敗と入力待ちが残るときだけ残す |
| 使い捨てのスクリプトと中間データ | その作業が終わったら消す。残す価値があるなら、結果をコミットするか `docs/research/` に書く |
| スクリプトの既定の出力 | 既定の出力先は固定名にして上書きする。日時を名前に入れて積み上げない |

`work/proposals/` の各ファイルは先頭に `削除:` の 1 行を置く。書けない提案は書かない。

## `docs/` の各文書は先頭に 3 行を置く

```
読者: <誰が、どの瞬間に読むか>
更新: <何が変わったら更新するか>
削除: <どうなったら削除するか>
```

## 使わない語

タスク ID (`T` + 数字)、`設計書 §N` / `企画書 §N` のような節番号での参照、
ブレスト、ユーザー決定、ユーザー判断、ユーザーが行う、実装担当、サブエージェント、担当モデル、
夜間、scratchpad、覆した、事故、教訓。書いた日の会話を前提にしている語である。
`npm run check` の `check:docs` (`scripts/check-docs.mjs`) が検出する。

## 節番号で参照しない

文書もコードコメントも、他の文書を節番号 (`§N`) で指さない。ファイル名と見出し語で指す。
節番号は再編でずれる。

## 測定値は日付とセットで書く

日付の無い数字は、古くなったことに誰も気づけない。
