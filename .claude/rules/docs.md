# 文書の規則

## 読者は「リポジトリしか持っていない人」

git に入る文書とコメントは最終成果物である。書いた日の会話を知らない読者が、
リポジトリの中身だけでその文を検証できなければ書かない。

書く前に 3 つ確かめる。

1. 会話を知らない読者が、この文を検証できるか
2. コードで表現できないか。できるなら文書に書かず、コードをファイル名で指す
3. この文書を削除する条件を書けるか。書けない文書は作らない

## 何をどこに書くか

| 情報の種類 | 置き場所 | 書き方 |
|---|---|---|
| 何を作る / 作らない、対象、指標、データの扱いの方針 | `docs/product.md` | 現在形。節は `scripts/check-docs.mjs` の `PRODUCT_HEADINGS` だけ |
| システムの境界、依存方向、実行トポロジ、コンポーネント間の契約、不変条件 | `docs/architecture.md` | 現在形。節は `ARCHITECTURE_HEADINGS` だけ。型・スキーマ・URL・値・セレクタを書かず、一覧を列挙しない (列挙はコードの 1 か所を指す) |
| 境界か範囲を変えた決定の理由と、採らなかった代替案 | `docs/decisions/NNNN-<slug>.md` | 1 決定 1 ファイル。見出しは状況 / 決定 / 帰結 / 採らなかった案。状態行は `状態: accepted (日付)` か `状態: superseded (日付)` |
| 外部サイトの制約 (robots.txt と利用規約の引用とそこからの判断、レート間隔の根拠、使ってはいけない URL、落とし穴) | `docs/stores/<store>.md` | 事実と最終確認日。見出しは `check-docs.mjs` の `STORE_HEADINGS`。使う URL の形・取れる項目・セレクタは adapter のコードが持つので書かない |
| 日付つきの測定 | `docs/research/<topic>-<date>.md` | 書いたら数字を変えない。他の文書は数字を写さずリンクする |
| 作業の進め方の規則 | `CLAUDE.md`、`.claude/rules/*.md` | 規則 + 理由 1 行。前者は常時、後者は該当パスを触ったときだけ読み込まれる |
| 型、スキーマ、値、アルゴリズム、URL の形、セレクタ、打ち切り条件 | コード | 文書に書かない |
| 1 モジュールに収まる機能の設計 | そのモジュール先頭のコメントとテスト | 文書を作らない |
| 定数・分岐の理由 | その行のコメント | 「なぜ」だけ。「何が起きたか」は書かない |
| 進行、担当、次の作業、ユーザーへの依頼、未決の提案、下書き | `work/` (git 管理外) | 形式自由。消す条件は下の「`work/` の寿命」 |
| 出来事の記録 (何が起きた、何回目、誰が) | コミットメッセージ | 文書とコメントに書かない |

同じ事実を 2 か所に書かない。出典を 1 つ決め、他はそこをファイル名で指す。

この表のうち機械で見られるもの (ヘッダ、見出しの型、決定の状態行、指したファイル・見出し・
`npm run` の実在、README のコマンド一覧) は `npm run check` の `check:docs` (`scripts/check-docs.mjs`) が見る。
規則を足すときは検査も足す。足せないものだけを文章で残す。

## `work/` の寿命

`work/` は形式自由だが、**消す条件の無いファイルを置かない**。git に入らないので、
古くなっても差分にも CI にも出ず、誰も気付かない。

| 置くもの | 消すとき |
|---|---|
| `work/status.md` | 消さない。書き足さずに上書きする。数字と状態には出どころと確認日を添える |
| `work/proposals/<topic>-<date>.md` | 決定が `docs/decisions/` に入るか、実装が main に入ったら消す |
| ユーザーへの依頼の下書き | 依頼を出したら消す |
| 実行の記録 (issue-batch の `<run>/` など) | その実行が終わったら消す。失敗と入力待ちが残るときだけ残す |
| 使い捨てのスクリプトと中間データ | その作業が終わったら消す。残す価値があるなら、結果をコミットするか `docs/research/` に書く。コミットした実行ファイルは、`package.json`・ワークフロー・`.claude/` のどこからも呼ばれていなければ `check:entrypoints` が落とす |
| スクリプトの既定の出力 | 既定の出力先は固定名にして上書きする。日時を名前に入れて積み上げない |

`work/proposals/` の各ファイルは先頭に `削除:` の 1 行を置く。書けない提案は書かない。

## `docs/` の各文書は先頭に 3 行を置く

```
読者: <誰が、どの瞬間に読むか>
更新: <何が変わったら更新するか>
削除: <どうなったら削除するか>
```

## 使わない語

書いた日の会話を前提にしている語 (タスク ID、節番号での参照など)。一覧は `scripts/check-docs.mjs` の
`FORBIDDEN_PATTERNS` が持ち、`check:docs` が検出する。

## 節番号で参照しない

文書もコードコメントも、他の文書を節番号 (`§N`) で指さない。ファイル名と見出し語で指す。
節番号は再編でずれる。「文書のパス + の「見出し」」の形で指した見出しが実在するかは `check:docs` が見る。

## 測定値は日付とセットで書く

日付の無い数字は、古くなったことに誰も気づけない。
