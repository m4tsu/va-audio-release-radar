# ドキュメントの入口

読者: このリポジトリを初めて開いた人
更新: 文書を足したり消したりしたら
削除: しない

何をどこに書くかの判定表は [`.claude/rules/docs.md`](../.claude/rules/docs.md)。
作業の規則はここではなく [`CLAUDE.md`](../CLAUDE.md) と [`.claude/rules/`](../.claude/rules/) にある。

| 文書 | 何が書いてあるか | いつ読むか |
|---|---|---|
| [`product.md`](./product.md) | 何を作る / 作らない、対象、指標、データの扱いの方針 | 機能を足す・削る前 |
| [`architecture.md`](./architecture.md) | コンポーネントの境界、依存方向、コンポーネント間の契約、不変条件 | コンポーネントをまたぐ変更の前 |
| [`decisions/`](./decisions/) | 境界か範囲を変えた決定の理由と、採らなかった案 | 「これは検討済みか」を確かめるとき |
| [`stores/`](./stores/) | 外部サイトの制約。robots.txt の引用、使える URL の形、取れる項目、落とし穴 | **`crawler/` を触る前に必ず** |
| [`research/`](./research/) | 日付つきの測定。書いたら数字を変えない | 決定の数字を確かめたいとき |

実装の事実 (型、スキーマ、値、URL の形、取得手順) は文書ではなくコードが正。
各モジュールの先頭コメントとテストが、そのモジュールの設計を書いている。

進行中の作業、次の作業、未決の提案は git 管理外の `work/` にある。
