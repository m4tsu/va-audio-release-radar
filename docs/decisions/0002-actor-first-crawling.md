# 取得は声優起点。ストアの全件取得はしない

読者: ストアの取得方式 (声優ごとの検索 / 新着一覧 / 全件) を変えようとする人
更新: 取得方式を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: superseded (2026-09-20)。[`0007`](./0007-daily-crawl-from-store-feeds.md) が置き換える。
全件取得をしない判断はそのまま引き継ぐ

## 状況

対象声優が AniList から決まる ([`0001`](./0001-target-actors-from-anilist.md)) ので、ストア側から
声優を発見する必要が無い。一方、robots.txt の `Crawl-delay` を守ると、ストアの全カタログを辿る
コストは対象声優ぶんの検索より 1 桁以上大きい (所要時間の比較は `docs/stores/dlsite.md` の「レート間隔」)。

## 決定

ストアは声優単位で引く (名前の完全一致検索、または声優タグ)。sitemap や一覧による全件取得はしない。
ストアが表示する作品数と sitemap の URL 数は別物なので、コストの見積もりは sitemap を実際に数えて行う。

## 帰結

- 声優数 × ストア数 × 間隔 が 1 回のクロールの所要時間になる。対象声優の全員を毎日回すには
  GitHub Actions の実行時間上限に収まらない。日次の新着検出をどう回すかは未決
  (調査は `docs/research/new-release-feeds-2026-09-19.md`)
- 名前で引けないストア (ポケットドラマ CD) は、事前に作った声優タグ辞書に無い声優を引けない

## 採らなかった案

- sitemap で全件を発見して声優を洗い出す (対象外の声優の発見にしか要らない)
