# クローラーは Worker の外で動かし、HTTP で取り込む

読者: クローラーの実行場所や DB への書き込み経路を変えようとする人
更新: 実行場所か経路を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-18)

## 状況

Cloudflare Workers には外向き通信とサブリクエスト数の上限があり、数千人ぶんのストア取得を
Worker 内で回すのに向かない。一方、D1 に触るコードが 2 か所に分かれると、スキーマ変更のたびに両方を揃える必要がある。

## 決定

クローラーは Node.js で Worker の外 (GitHub Actions か手元) で動かす。D1 には直接書かず、
Worker の管理 API に正規化済み JSON を HTTP で送る。境界は Zod で検証し、ペイロードに版を持たせる。

## 帰結

- クローラーは数時間走り、その間に Worker が差し替わりうる。版の不一致は 409 で走行を止める
- 取得の失敗も保存の失敗も、必ず管理 API 経由で記録する。記録の無い失敗は「作品 0 件」と区別できない
- レートリミッタはプロセス内の状態になる。同じホストを 2 プロセスから叩かない運用が要る

## 採らなかった案

- Worker の cron trigger 内で取得する (通信上限)
- クローラーから D1 に直接書く (DB を触るコードが分散する)
