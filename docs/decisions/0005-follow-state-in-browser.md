# フォロー状態はブラウザ内に持ち、アカウントを作らせない

読者: フォローの保存先や認証を変えようとする人
更新: 通知の実装でサーバー側にフォローを持つことにしたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-18)。通知の設計で見直しが予定されている

## 状況

閲覧・検索・フォローはアカウント無しで使えるようにしたい。パスワード認証は導入しない。

## 決定

フォロー状態と既読の日時はブラウザの IndexedDB にだけ持つ。サーバーはフォローを知らない。
フォロー中の新着はブラウザがフォロー ID をまとめて送り、サーバーが引き直す。

## 帰結

- SSR ではフォローが読めないので、フォローに依存する部分はマウント後に描く
- 端末をまたいでフォローは同期されない
- 通知を実装するには宛先が要る。ログインした利用者のフォローをサーバーに同期する二重経路か、
  ブラウザ単位の Web Push か、どちらにするかは未決

## 採らなかった案

- 最初からアカウントを必須にする (閲覧の入口が狭くなる)
