# 日次はストアの新着一覧を照合し、声優起点は初期構築と補完に限る

読者: ストアの取得方式 (新着一覧 / 声優ごとの検索 / 全件) や取得の周期を変えようとする人
更新: 方式か周期を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-20)。[`0002`](./0002-actor-first-crawling.md) を置き換える

## 状況

声優起点で対象声優の全員を回すと、DLsite だけで GitHub Actions のジョブ時間の上限を超えうる
([`new-release-feeds-2026-09-19.md`](../research/new-release-feeds-2026-09-19.md) の「初期構築」)。同じ測定で、
DLsite と Audible には robots.txt が許す新着一覧があり、1 日ぶんを数分で取り切れる。ポケットドラマ CD の一覧は未検証。

## 決定

- **日次**: 各ストアの新着一覧を取り、出演者名を対象声優に照合して、当たった作品だけ保存する。照合は Worker が行う
- **月次**: 作品を持つ声優を声優起点で引き直し、新着一覧の取りこぼしを埋め、検索の上限に当たった声優を洗い出す。
  DLsite の既知作品の詳細を取り直して販売終了を観測する ([`0008`](./0008-no-price-no-availability.md))
- **シーズンごと**: AniList から増えた声優だけを声優起点で引く。**別名義を足したとき**: その名前で 1 回引く
- **初期構築**: 全員を 1 回だけ声優起点で回す。GitHub Actions の外で行う。全件取得はしない (0002 のまま)

## 帰結

- 対象声優が 1 人も解決できない作品は保存しない。走行主体が 2 つになるので、同じホストの実行権を Worker が 1 つだけ貸す
- 日次の走行は件数が日ごとに揺れるので、健全性は前回比ではなく「直近に成功した取り込みがあるか」で見る
- Audible で出演者欄が空の作品は日次で拾えず、月次の補完まで遅れる。作品 0 件の声優は月次の対象外なので拾えない

## 採らなかった案

- 対象外の作品を隔離して一定期間置き、別名義が増えたら再照合する。声優起点の引き直しで足り、隔離した場所の運用が増える
- 出演者名を対象声優に解決できたものだけ持ち、未解決クレジットの仕組みを無くす。人手は減るが、解決済みの作品の共演者名も失う
- 声優起点を分割して毎日回す。新着の検出が数日遅れ、ストアへの往復が声優の人数に比例したままになる
