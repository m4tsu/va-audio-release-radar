# 日次はストアの新着一覧を照合し、声優起点は初期構築と補完に限る

読者: ストアの取得方式 (新着一覧 / 声優ごとの検索 / 全件) や取得の周期を変えようとする人
更新: 方式か周期を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-20)。[`0002`](./0002-actor-first-crawling.md) を置き換える

## 状況

声優起点で対象声優の全員を毎日回すと、DLsite だけで GitHub Actions のジョブ時間の上限を超える
([`0002`](./0002-actor-first-crawling.md) の帰結)。一方、各ストアには robots.txt が許す新着一覧があり、
1 日の新作は 3 ストア合わせて数十件で、数分で取り切れる
([`new-release-feeds-2026-09-19.md`](../research/new-release-feeds-2026-09-19.md))。

## 決定

- **日次**: 各ストアの新着一覧を取り、出演者名を対象声優に照合して、当たった作品だけ保存する。
  照合は Worker が行う (管理画面で足した別名義は Worker にしか無い)
- **月次**: 作品を持つ声優を声優起点で引き直す。新着一覧の取りこぼし (Audible の出演者欄が空の作品) を埋め、
  検索の上限に当たった声優を洗い出し、DLsite で販売終了になった作品を外す
- **シーズンごと**: AniList から増えた声優だけを声優起点で引く
- **初期構築**: 全員を 1 回だけ声優起点で回す。GitHub Actions の外で行う。全件取得はしない (0002 のまま)

## 帰結

- 対象声優が 1 人も解決できない作品は保存しない。別名義を後から足したときは、その名前で声優起点に 1 回引き直す
- 走行主体が 2 つになるので、同じホストの実行権を Worker が 1 つだけ貸す仕組みが要る。
  日次の走行は件数が日ごとに揺れるので、前回比で警告する健全性の判定は使えない
- Audible の新着検出は、月次の補完に回る分が最大 1 か月遅れる

## 採らなかった案

- 対象外の作品を隔離して一定期間置き、別名義が増えたら再照合する。別名義の追加は年に数回で、声優起点の引き直しで足りる
- 声優起点を分割して毎日回す。上限には収まるが、新着の検出が数日遅れ、ストアへの往復が新着一覧の 100 倍になる
