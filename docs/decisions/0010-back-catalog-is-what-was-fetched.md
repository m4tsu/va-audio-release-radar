# back catalog は取得できた範囲と定義する

読者: 網羅率を上げようとする人。声優ページに全作品が無い理由を説明する人
更新: 網羅を約束する判断をしたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-20)

## 状況

各ストアの検索は取れる件数に上限を置いている。DLsite は robots.txt の意図に従って検索を 1 ページ目に固定し
([`dlsite.md`](../stores/dlsite.md) の「既知の落とし穴」)、Audible は同姓の別人の作品で往復が無駄になるのを避けて
ページ数の上限をこちらで置いている ([`audible.md`](../stores/audible.md) の「2 ページ目以降」)。
上限を超える作品数の声優では back catalog が欠ける。

## 決定

back catalog は「上限の範囲で取得できた作品」と定義し、網羅を約束しない。どちらの上限も上げない。
上限に当たった声優のページには、ストアでその声優の全作品を見るリンクを出す。取りこぼしは監視するが、埋める義務は持たない。

## 帰結

- 網羅率の記録 (総件数と、取り切れたかの真偽) は埋めるためではなく利用者に示すために残す
- 上限に当たった声優は月次の補完巡回で洗い出す ([`0007`](./0007-daily-crawl-from-store-feeds.md))

## 採らなかった案

- DLsite の 2 ページ目以降を取る。robots.txt の字面では許されるが、ページ送りを避けたいという意図に反する
- Audible のページ数の上限を上げる。上限に当たる声優の大半は同姓の別人を引いており、往復が増えるだけ
- Audible の並び順を増やして和集合を取る。robots.txt が禁じている
