# ステラプレイヤーを新着一覧起点で追加する

読者: 対応ストアを足す / 外すことを考える人。ステラプレイヤーの取得方式を変えようとする人
更新: 追加を取りやめたら、または取得の起点を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-20)

## 状況

[`store-survey-2026-09-18.md`](../research/store-survey-2026-09-18.md) は「声優から作品への導線が無い」
を理由にこのストアを保留にした。[`0007`](./0007-daily-crawl-from-store-feeds.md) で日次の起点が
新着一覧に変わり、その導線は追加の条件ではなくなった。制約は
[`stores/stellaplayer.md`](../stores/stellaplayer.md)、測定は
[`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md)。

## 決定

対応ストアに追加する。取得の起点は 3 つのカテゴリトップの新着一覧と、そこから引く商品ページに限る。

- **日次**: `/general` `/bl` `/girls` を引き、既知でない商品 ID の商品ページを引く
- **初回**: 商品 ID を 1 から最大まで 1 巡する。GitHub Actions の外で 1 回だけ (0007 の「初期構築」)
- **レート間隔は既定値のまま**。短くしてよい根拠が相手側に 1 つも無い
- 声優起点の巡回は行わない。声優のページが存在しない

## 帰結

- 月次の補完巡回 (0007) の対象から外れる。取りこぼしは日次の新着一覧だけで防ぐ
- 対象声優の判定は商品ページを引いた後になる。一覧に出演者が無いため
- 初回の 1 巡は大半が対象声優を含まない商品に費やされる。1 回だけなので受け入れる

## 採らなかった案

- 追加しない。当たる層は日次数リクエストで押さえられ、費用がほぼかからない
- `api.stellaplayer.jp` の GraphQL を使う。別ホストで規約も枠も調べていない。HTML だけで足りる
- 初回の 1 巡をせず新着一覧だけで前へ進む。back catalog が主内容 ([`product.md`](../product.md) の「製品」)
