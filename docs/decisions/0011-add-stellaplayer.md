# ステラプレイヤーを新着一覧起点で追加する

読者: 対応ストアを足す / 外すことを考える人。ステラプレイヤーの取得方式を変えようとする人
更新: 追加を取りやめたら、または取得の起点を変えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-20)

## 状況

[`store-survey-2026-09-18.md`](../research/store-survey-2026-09-18.md) は「声優から作品への導線が無い」
を理由にこのストアを保留にした。その後 [`0007`](./0007-daily-crawl-from-store-feeds.md) で日次の起点が
ストアの新着一覧に変わり、声優起点の導線は追加の条件ではなくなった。
robots.txt が無く、利用規約にも情報解析を禁じる条項が無いことを確認した
([`stores/stellaplayer.md`](../stores/stellaplayer.md))。測定は
[`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md)。

## 決定

対応ストアに追加する。取得の起点は 3 つのカテゴリトップの新着一覧と、そこから引く商品ページに限る。

- **日次**: `/general` `/bl` `/girls` を引き、既知でない商品 ID の商品ページを引く。
  新着 10 件が覆う幅は最も短いカテゴリでも 22 日あるので、日次なら取りこぼさない
- **初回**: 商品 ID を 1 から最大まで 1 巡する。4 時間ほどなので GitHub Actions の外で 1 回だけ回す
  (0007 の「初期構築」)
- **レート間隔は既定値のまま**。短くしてよい根拠 (robots の指定、公開されている API 枠) が 1 つも無い
- 声優起点の巡回はこのストアでは行わない。声優のページが存在しない

## 帰結

- 月次の補完巡回 (0007) の対象から外れる。取りこぼしは日次の新着一覧だけで防ぐ
- 一覧に出演者が無いので、対象声優の判定は商品ページを引いた後になる。
  日次で引く商品ページは 1 日あたり 1 件に満たない
- 発売日が全商品に入るので、ポケットドラマ CD のように日付の意味が変わる作品は増えない
- 初回の 1 巡は 9 割以上が対象声優を含まない商品に費やされる。1 回だけなので受け入れる

## 採らなかった案

- 追加しない。当たる層 (ドラマ CD) は日次 4 リクエストで押さえられ、費用がほぼかからない
- `api.stellaplayer.jp` の GraphQL を使う。別ホストで、規約も枠も調べていない。HTML だけで足りる
- 初回の 1 巡をせず新着一覧だけで前へ進む。back catalog が主内容
  ([`product.md`](../product.md) の「製品」) なので、一度は舐める
