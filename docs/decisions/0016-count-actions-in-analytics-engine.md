# 指標の分母は Web Analytics、分子の操作は Workers Analytics Engine で数える

読者: 指標の計測手段、画面からサーバーへ送るもの、利用者のブラウザが読み込む外部のものを変えようとする人
更新: 計測手段を替えたら superseded にして新しい決定を書く
削除: superseded になっても消さない

状態: accepted (2026-09-25)

## 状況

[`product.md`](../product.md) の「製品」は 2 つの率を見ると決めているが、計測する手段が無かった。
Cloudflare Web Analytics はページビューしか数えられず、任意のイベントを送れない
([`research/analytics-options-2026-09-25.md`](../research/analytics-options-2026-09-25.md))。

## 決定

分母のページビュー (声優ページ、作品ページ) は Cloudflare Web Analytics で数える。
分子の操作 (フォロー、作品ページでのストアへのリンクと Audible の無料体験のリンク) は、
画面が `/api/event` に送り、Worker が Workers Analytics Engine に書く。どちらも Workers Free の範囲で費用が掛からない。
送るのは操作の種類と、ストアの別・フォローを押した場所だけ。どちらも 1 つの設定 (Web Analytics のトークン) が空なら止まる。

送客は、どこから来た人が押したかを分けずに、作品ページのストアへのリンクをすべて数える。
通知はフォロー一覧を開き、ストアへの直リンクを持たないので、通知からの送客も必ず作品ページを通る。
通知から来た人だけを分けるには通知を開いた回数と入口の印が要り、それは範囲に入れていない。

フォローは、声優ページに限らずフォローボタンのあるすべての場所で数え、押した場所を付ける。
声優ページ → フォローの転換率は場所で絞って出す。声優一覧やアニメページからのフォローも
通知の宛先になるので、数えなければフォローの実数と入口ごとの使われ方が見えない。

## 帰結

- フォローの状態はブラウザの外に出ない ([`0005`](./0005-follow-state-in-browser.md))。操作 1 件に声優 ID も付けない
- 利用者のブラウザが読み込む外部のものに Web Analytics の計測スクリプトが加わる。プライバシーポリシーに書く
- 送客のクリック率は全体の値で、通知から来た人に限った率ではない

## 採らなかった案

- 分子もページビューで代用する (押したら中間ページを挟む)。送客に 1 回の遷移が増え、フォローは遷移しない
- Zaraz、外部の解析サービス。数える先が第三者になり、操作の記録が外に出る
