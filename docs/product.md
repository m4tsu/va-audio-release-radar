# 何を作るか

読者: 機能を足す・削る・変える前の人。作ってよいものかを判定するときに読む
更新: 作るもの / 作らないもの / 対象 / 指標 / データの扱いの方針が変わったら
削除: しない (製品が終わるまで)

## 製品

アニメに出演している声優をフォローすると、その人の音声作品 (ASMR / 朗読 / ドラマ CD) を
複数ストア横断で追えるサービス。利用者の問いは「この声優の声が聴ける商品は何があるか。
新しく出たら教えて」であり、媒体の区別は二次的な絞り込みにすぎない。

アニメ本業の声優の音声作品は年に数本しか出ない。だから主内容は **カタログ全体 (back catalog)** で、
新着はその上に載せる層。製品の性質は「頻繁に見に来るフィード」ではなく
「めったに鳴らないが、鳴ったら確実に届く通知」。

見る指標は 2 つ。声優ページ → フォロー (通知登録) の転換率と、通知 → ストア送客のクリック率。
フィードの閲覧数は指標にしない。

## 作らないもの

ASMR 推薦サイト、声優事典 / キャスト DB、価格追跡、AI 推薦、SNS。
機能を足すときの判断規則は「この機能はフォロー情報があるから成立するか」。成立しないなら他社でもできるので作らない。

- アニメとゲームは声優に入る入口としてだけ持つ。音声作品を買うのは声優の熱心なファンで、アニメやゲームの
  ファンが、声優のファンになる前に出演者のその作品と関係のない音声作品を求めることはないため。
  あらすじ・話数・放送局・キャラ性能は持たない
  (ゲームは [`decisions/0017`](./decisions/0017-games-as-entry-to-actors.md))
- 共演バッジは作らない
- パスワード認証、Redis、ジョブキュー、別名義の推測マージは導入しない

## 対象声優

**対象声優 = AniList にアニメ出演記録がある日本語声優。** 実行日から決めた直近 12 シーズンのアニメの
日本語 voiceActors を、1 作品あたりの人数で切らずに機械的に集める。人が名前を挙げない。
DLsite にしか居ない同人 ASMR の声優はフォロー対象にしない (クレジット表記としては保存する)。

対象声優の大半は音声作品を出していない。その声優もフォローできる。出演アニメがあればページを出し、
音声作品がまだ無いことを画面に書く。そのページは検索エンジンには載せない (sitemap に出さず noindex)
([`decisions/0012`](./decisions/0012-follow-actors-without-works.md))。

台帳は DB で、行は消さない。12 シーズンという窓も 1 シーズンあたりの作品数も取得範囲を絞る条件であり、
範囲から外れた声優を消す理由にしない。改名は別名義として扱う
([`decisions/0009`](./decisions/0009-actor-list-append-only.md)、[`decisions/0015`](./decisions/0015-db-is-the-ledger.md))。

対象シーズンの決め方と slug の規則はコードが正 (`crawler/discovery/anilist.ts`、`src/domain/actor-slug.ts`)。

## 対象作品

- **全年齢と BL を載せる。R18 は載せない。** R18 を載せても対象声優の作品は増えず (2026-09-18 の測定、
  `docs/research/adult-scope-2026-09-18.md`)、Amazon アソシエイトの参加条件に抵触して Audible の送客経路を
  失うリスクだけが残る。BL を外すと男性声優の対象作品を大きく失う
- 年齢区分は真偽値ではなく列挙で持つ。区分を公開していないストア (Audible) の作品を「全年齢」と言い切らない
- BL は年齢区分ではなく内容の区分。ストア固有の区分として解釈せずに保存する
- 同じ作品が複数ストアにあっても、当面は別作品として扱う。同一と言える根拠が無いものをマージしない
- **対象声優が 1 人も出ていない作品は保存しない。** ストアの新着一覧から取り込むときの前提
  ([`decisions/0007`](./decisions/0007-daily-crawl-from-store-feeds.md))
- **価格と在庫状態は持たない。** 作品ページはストアへの導線で、価格はストアで見る。ストアが販売終了を
  明示した作品だけ取り下げる ([`decisions/0008`](./decisions/0008-no-price-no-availability.md))
- **back catalog は規約の範囲で取得できた作品。** 網羅は約束せず、検索の上限に当たった声優には
  ストアでその声優の全作品を見るリンクを出す ([`decisions/0010`](./decisions/0010-back-catalog-is-what-was-fetched.md))

## 新着

- **新着は発売日基準。** 発見日だけで判定すると、初回クロールと声優追加のたびに全作品が新着になる
- フィードは 今後の発売 / 最近の新作 / それ以前 の 3 段。上 2 段が空でも画面が空にならない
- 発売日の無い作品 (Audible のポッドキャスト、ポケットドラマ CD 全般) だけ、その声優の初回クロール以降に
  見つかったものを新着扱いにする。**1 ストアだけ日付の意味が違う**ことを UI で明示する
- 未読は「最後にフィードを見た日時」との比較で決める。アカウント無しで既読を実現する

## 通知

新作が出た週だけ 1 通のダイジェスト。空の週は送らない。RSS は主手段にしない。
手段は Web Push で、アカウント無しで購読できる ([`0013`](./decisions/0013-push-subscription-holds-follows-on-server.md))。
閲覧・検索・フォローもアカウント無しで使える。メールと、ログインによる端末間のフォロー同期は無い。
入れるなら、登録はパスワードやメールアドレスの直接入力をさせず OAuth で行う。

セール / 予約 / 無料になったことの通知は需要があるが、今は持たない。知るには既知の作品の状態を取り直し続ける
必要があり、その往復と運用の手間に見合わないため (価格を持たないことは
[`decisions/0008`](./decisions/0008-no-price-no-availability.md))。

## 別名義

**別名義は、信頼できる情報に基づく場合に限り紐付ける。** 根拠として認めるのは、本人・事務所の公表情報、
ストア自身が同一人物として扱っている事実、出典のある公開情報。声質・作風・活動時期からの推測、LLM の判断、
運用者の心証は認めない。間違えたときの被害 (実在の人物に、公表していない出演作を結び付ける) が大きいため、
迷ったら紐付けない。

対象声優に解決できなかった出演者名は作品に残し、管理画面の未解決キューに出す。対象声優でない名義には
「対象外」の印を付けてキューから外す。別名義を足したら、その名前で声優起点に引き直して過去の作品を拾う。

掲載内容の誤りは、作品ページと声優ページからお問い合わせとして受け取る。申し出は未解決キューと自動で
結び付けない。届いた申し出は、根拠として認めるものに当たるかを確かめてから反映する。

## 差別化の軸

「フォローした声優の新着を、ストアを問わず取りこぼさず知らせる」。ストア横断はその手段。
作品には出演形態 (単独 / 少人数 / 全編朗読 / 大人数) を持たせる。クレジットの人数で判定でき、
back catalog 中心の設計とかみ合う。
