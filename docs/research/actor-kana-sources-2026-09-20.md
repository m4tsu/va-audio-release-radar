## 0. 調査方法

- 対象声優は `crawler/actors.generated.json` の **2,569 人** (2026-09-20 時点)。うち手書きのかながあるのは
  **35 人**、名前がかなだけで書かれているのは **73 人** (ひらがなのみは 41 人)。
  **対象人数は AniList 側の登録が変われば動く。**本書の割合は、この 2,569 人から取った標本の値である
- 取得は `work/` に置いた使い捨てのスクリプトから行った (git には残していない)。
  クローラー本体は変えていないので、`crawler/` からこの調査を再現することはできない。条件は次のとおり
  - robots.txt を最初に取り、禁止パスには触れていない。かなを取るために引いたのは
    `/wiki/<記事名>` と `/wiki/<Q id>` だけ。ほかに robots.txt と規約・ライセンスのページ、
    dump の一覧ページを引いた (下の表)
  - スクリプトは 1 ホストあたり 5 秒の間隔を空け、リダイレクトは追わない
  - UA: `va-audio-release-radar-bot (https://github.com/m4tsu/va-audio-release-radar)`、
    `Accept-Language: ja-JP,ja;q=0.9`。ブラウザ相当の UA を使わない理由は
    [`docs/stores/wikimedia.md`](../stores/wikimedia.md) の「既知の落とし穴」。
    **調査した時点の `crawler/lib/fetch.ts` はブラウザ相当の UA を全ホストに送っていたので、
    この UA は出せなかった。**同じ手順をクローラーから再現するには、
    UA をホストで振り分けられるようにする必要があった
  - 例外として、調査を始めた時点で引いた次の 11 件だけはブラウザ相当の UA で投げた。
    `ja.wikipedia.org` / `www.wikidata.org` / `query.wikidata.org` / `meta.wikimedia.org` /
    `foundation.wikimedia.org` の robots.txt (5 件)、meta と foundation の User-Agent policy (2 件)、
    `wikitech.wikimedia.org` の Robot policy、foundation の API usage guidelines、
    `Wikidata:Licensing`、`Wikipedia:ウィキペディアを二次利用する` (各 1 件)。

  乱数を使っていないので同じ標本を作り直せる

## 1. 結論

- **日本語版 Wikipedia の記事から、標本 200 人中 149 人 (74.5%) のかなが取れる。**
  誤りを混ぜないための条件 (下記) を満たしたものだけを数えている
- **手書きのかながある 35 人は全員取れ、35 人とも手書きの値と一致した** (空白とカタカナを畳んだ比較)
- **Wikidata は単独では使えない。** 名前から項目を引く経路 (SPARQL・API・`Special:Search`) が
  robots.txt で塞がれており、Wikipedia の記事に埋まっている項目 id を経由するしかない
  ([`docs/stores/wikimedia.md`](../stores/wikimedia.md))。
  経由できた 61 件のうち 56 件 (91.8%) にかながあり、Wikipedia 側と両方取れた 52 件のうち
  食い違いは 1 件だった
- **AniList にかなの項目は無い** ([`docs/stores/anilist.md`](../stores/anilist.md) の「取得できる項目」)

## 2. 日本語版 Wikipedia

`/wiki/<記事名>` を対象声優の名前で 1 人 1 回引き、取れなかった名前だけ `<名前>_(声優)` で引き直した
(名前に空白がある 2 人だけは、空白を `_` に直した記事名で引き直した)。

| 標本 200 人の結果 | 人数 |
|---|---:|
| 記事名そのままで取れた | 140 |
| `_(声優)` で引き直して取れた | 9 |
| **かなが取れた合計** | **149 (74.5%)** |
| 記事が無い (404) | 23 |
| 記事はあるが声優のカテゴリが無い | 17 |
| 曖昧さ回避のページ | 4 |
| 別の記事に転送された | 5 |
| 名前に空白があり、`_` に直しても記事が無い | 2 |

かなの出どころは **`Template:声優` の `ふりがな` 引数 (記事 HTML の `data-mw` 属性に残る) が 144 件**、
**名前そのものがかなで記事に読みが無いものが 5 件**。
導入部の括弧からしか取れなかった例は 0 件で、**導入部だけを見る理由は無い**。
両方が取れた 142 件のうち食い違いは 1 件 (`麦人`) で、これは導入部の側の取り違えだった
(読みの直後に脚注が入る記事で、別の段落の括弧を拾った)。`ふりがな` 引数のほうが素直に取れる。

取れたかなの表記は **149 件中 141 件が姓名の間に空白を含み、3 件がカタカナを含む**
(`ソンド` / `御堂ダリア` = みどう ダリア / `松浦チエ` = まつうら チエ)。
手で書いた既存のかな (`crawler/actors-overrides.json` の `nameKana`) は空白無しのひらがななので、
そのまま入れると表記が混ざる。

## 3. Wikidata

Wikipedia の記事 HTML に入っている項目 id を使って `/wiki/<Q id>` を 92 件引いた。

| 結果 | 件数 |
|---|---:|
| 引いた項目 | 92 |
| P1814 (name in kana) を単独の主張として持つ | 81 |
| P1814 を他の主張の限定子としてだけ持つ | 6 |
| かなが無い | 5 |

P1814 が付いていた先の延べ数は **P1814 の主張が 81、P1559 (name in native language) が 17、
P1477 (birth name) が 5、P742 (pseudonym) が 1、P2562 (married name) が 1**。
**P2562 は結婚後の姓なので、限定子を無差別に拾うと別の読みが入る。**

標本の 61 件では **56 件 (91.8%) にかながあり**、Wikipedia 側でもかなが取れた 52 件のうち
**食い違いは 1 件** (`高仲佑星`: Wikipedia「たかなか ゆうせい」/ Wikidata「たかなか ひろゆき」)。
手書きのかながある 35 人は 35 件ともかながあり、35 件とも手書きの値と一致した。

Wikipedia 側では取れず Wikidata にだけあったのは 4 件で、いずれも
「記事はあるが声優のカテゴリが無い」人 (俳優・歌手として立項されている人) だった。

## 4. 同名の別人を取り違えない条件

**次の 3 つを全て満たす記事からだけ取る。1 つでも欠けたら取らない。**

1. 要求した記事名と、着地した記事名 (`wgPageName`) が一致する (リダイレクトで別の記事に
   移されていない)。要求してよい記事名は `<名前>` と `<名前>_(声優)` の 2 通りだけ
2. カテゴリに「声優」を含む語がある (「日本の女性声優」など)
3. 曖昧さ回避のカテゴリを持たない

条件を課さずに「1 回目の取得が 200 で返り、読みが書いてあれば取る」とすると、標本 200 人では
**168 件取れる。そのうち 28 件は 3 条件を満たさない** (声優のカテゴリが無い 18 件、
曖昧さ回避のページ 8 件、別の記事に転送された 2 件。転送された 5 人のうち読みまで取れるのがこの 2 人)。
この 28 件と「2. 日本語版 Wikipedia」の表の内訳が合わないのは、表が引き直した後の状態を数えているため。
曖昧さ回避のページは全部で 12 件あり、そのうち 8 件で読みが取れた (この 8 件が上の内訳)。
12 件の行き先は、`_(声優)` で引き直して本人の記事が見つかった 8 件 (読みが取れていた 5 件と、
取れていなかった 3 件) が表の「取れた」側へ、見つからなかった 4 件 (読みが取れていた 3 件と、
取れていなかった 1 件) が表の「曖昧さ回避 4 件」に残る。

**28 件のうち、読みそのものが別人・別団体のものになるのは転送された 2 件。**
残りは読みとしては正しいことが多いが、**その記事が対象の声優本人のものかを機械で確かめられない**。
実例:

- `朝ノ瑠璃` → `朝ノ姉妹ぷろじぇくと` に転送され、読みは「あさのしまいぷろじぇくと」になる
- `木花藍` → `賢プロダクション` に転送され、読みは「けんプロダクション」になる
- `天野聡美` → 曖昧さ回避のページから「あまの さとみ」が取れてしまう。
  本人の記事は `天野聡美_(声優)` にあり、引き直せば本人の記事から同じ読みが取れる
- `吉田早希` → 曖昧さ回避のページから「よしだ さき」が取れてしまう。
  `吉田早希_(声優)` は無く、**この人が曖昧さ回避に挙がっているどの人物なのかは分からない**

**条件 2 は、俳優・歌手として立項されている人を落とす。**
標本では 18 人が該当し、引き直しても 17 人が残る。
そのうち Wikidata を引いた 4 人 (`満島ひかり` `染谷将太` `永瀬廉` `田村升吾`) は 4 人とも読みを持っていた。
読みは合っているが、**記事が本人のものかどうかを機械で確かめる手がかりがこの条件しかない**ので、
落とす側を採る。

## 5. 取得コスト

- **1 人 1 リクエスト。** 5 秒間隔で 2,569 人を 1 回ずつ引くと **12,845 秒 = 約 3.6 時間**。
  引き直しが標本と同じ割合 (200 人中 60 人) で要るとすると、合計は約 4.6 時間 (推測)
- Wikidata を併用すると、Wikipedia の記事を引いたうえで 1 人 1 リクエストが加わる
- 日本語版 Wikipedia の記事 dump (`jawiki-latest-pages-articles.xml.bz2`) は
  **4,730,918,124 バイト** (2026-09-02 版、2026-09-20 に一覧ページで確認)。
  運営者の Robot policy が live リクエストより dump を先に検討するよう書いている
  ([`docs/stores/wikimedia.md`](../stores/wikimedia.md) の「使う URL」)。
  dump からの抽出は試していない

## 6. 調べなかった候補と、その理由

| 候補 | 状態 |
|---|---|
| 各声優事務所の公式サイト | **取得していない。** 規約・robots.txt・ライセンスを引用できないので、採否を判定しない |
| MyAnimeList / VGMdb などのアニメ・音楽系データベース | 同上 |
| 対応ストア (DLsite / Audible / ポケットドラマ CD) のタグ・出演者名 | **そもそもかなを持っているかどうかを確かめていない。** 制約は [`docs/stores/`](../stores/) に引用済み |
| AniList | 取得済みの供給元だが、**かなの項目が無い** ([`docs/stores/anilist.md`](../stores/anilist.md)) |

引用の無い候補は「取ってよいか分からない」であって「取ってはいけない」ではない。
必要になったら、robots.txt と利用規約の確認から始める。
