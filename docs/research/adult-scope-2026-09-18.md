## 1. 調査 1: DLsite maniax (R18) に対象声優の本名義がどれだけ出ているか

### 1-1. robots.txt の確認

`https://www.dlsite.com/robots.txt` は `User-agent: *` の 1 グループのみ。`/maniax/` を名指しした禁止は無く、
`/home/` と同じ扱い。検索パスに関する条項も同じ。

```
Disallow: /*adultcheck/
Disallow: /js/adultcheck.js
Disallow: /*/fsr/=/*/per_page/*/page/
Allow: /*/fsr/=/*/per_page/*/page/1/
Crawl-delay: 10
```

年齢確認そのもの (`/*adultcheck/`、`/js/adultcheck.js`) は禁止されている。本調査ではこれらに一切アクセスしていない。
sitemap 宣言は 16 本あり、`maniax_index.xml` のほか `girls` / `bl` / `bldrama` / `garumani` など
年齢区分・客層別に分かれている。

### 1-2. 年齢確認の仕組み (DLsite)

**`/maniax/` の検索結果は、Cookie も年齢確認も無しで HTTP 200 で全件返ってくる。**

年齢確認はクライアント側 JavaScript でしか実装されていない。HTML に埋まっているのは次の分岐だけで、
サーバー側のフィルタリングは無い。

```js
if ((dlsite.isAdult() && dlsite.getId() !== 'circle' && !(dlsite.isFemale() && dlsite.isBooks()))
    || dlsite.forceAdultCheck) {
  $.importAdultcheck();   // /js/adultcheck.js を後から読み込む
}
```

`/js/adultcheck.js` は robots.txt で禁止されているため取得していない。Cookie 名は特定していない。
**特定する必要が無い**: 取得側から見ると年齢確認は存在しないのと同じで、Cookie を付けずに R18 の一覧が読める。

これが「フィルタされていない」ことは対照実験で確かめた (次項)。

### 1-3. 対照実験: maniax は本当に R18 を返しているか

キーワード無しで音声カテゴリ全体の総件数を `/home/` と `/maniax/` の両方で取った。

| `/maniax/` | **76,962** | 露骨な性的表現を含むタイトルが並ぶ (本書には引用しない) |

maniax 側は home の 8.6 倍で、1 ページ目の中身も明確に成人向け。
**Cookie 無しでも R18 が結果に含まれることが確定した。** 以降の「0 件」はフィルタの結果ではない。

なお maniax は home の完全な上位集合ではない (1-4 の斉藤壮馬)。
したがって 76,962 − 8,970 = 67,992 は R18 音声作品数の**概算**であって差集合の正確な値ではない。

## 2. 調査 2: ポケドラの年齢区分と BL 作品

### 2-1. サイトは 4 つのストアに分かれている

`store` クエリパラメータの値と、それぞれの作品総数 (キーワード無しの `list.php` の `N件中` から取得)。

| store の値 | 表示名 | 作品総数 | 年齢確認 | 一覧への到達 |
|---|---|---:|---|---|
| `men` | 一般 | **1,366** | 不要 | `list.php?store=men` |
| `bl` | BL | **911** | 不要 | `list.php?store=bl` |
| `adt` | オトナ向け | **4,373** | 必要 | `list.php?store=adt&age_check=1` + セッション Cookie |
| `adt-bl` | オトナBL | **317** | 必要 | 同上 |
| | **合計** | **6,967** | | |

**「女性向け」「乙女向け」という独立したストアは存在しない。** 区分は上の 4 つだけ。
オトナ向け (`adt`) が最大で、全体の 63% を占める。
`store` を省略すると `men` (一般) になる (og:url が `&store=men` を付けて返す)。

### 2-2. 年齢区分は機械的に取れるか

**取れる。ただし「作品に付いた R18 ラベル」ではなく「どのストアに属するか」という形で取れる。**

| 取得元 | 場所 | 例 |
|---|---|---|
| 一覧 | リクエストした `store` パラメータそのもの | `list.php?store=bl` の結果は全て BL |
| 作品ページ | パンくず 2 段目のリンク先 | `<li><a href="https://pokedora.com/?store=bl"><span>BL</span></a></li>` |
| 作品ページ | 検索フォームの `<select name="store">` の `selected` | `<option value="bl" selected>BL</option>` |

作品ページの `<select>` には 4 つの選択肢が常に全部出ていて、現在の作品が属するものだけに `selected` が付く。
パンくずと合わせて 2 経路あるので、パーサーの堅牢性は十分。

**取れないもの**: 作品単位の「R18」「18禁」といった明示ラベルは HTML のどこにも無い。
一覧の `<span class="product_catgory_el">` に入るのは `BLCD` のような**商品カテゴリ**であって年齢区分ではない。
年齢区分はストア所属から導くしかない。

### 2-3. 年齢確認の仕組み (ポケドラ)

自己申告のモーダル 1 枚。実装はこうなっている。

1. オトナ向け / オトナBL へのリンクは `href="#"` で、`onclick="view_age_check(undefined, 'adt')"` を呼ぶ
2. `view_age_check()` は `div#age_check_block` を表示するだけ。文面は
   「ここから先は、暴力表現・性描写など18歳以上の方を対象とした作品を取り扱うページとなります。
   18歳未満の方のアクセスは固くお断り致します。」「あなたは18歳以上ですか？（高校生を除く）」
3. 「はい」を押すと `location.href = '/?store=' + s + '&age_check=1'` へ遷移する
4. サーバーは `age_check=1` を受けて `ECSESSID` セッション Cookie に状態を記録する

**技術的な取得可否: 可能。** 実証済み。

| 試したこと | 結果 |
|---|---|
| `list.php?store=adt` (Cookie 無し・`age_check` 無し) | HTTP 200。作品 0 件。ページ内に年齢認証モーダルの HTML が含まれる |
| `list.php?store=adt&age_check=1` (Cookie jar 付き) | HTTP 200。`ECSESSID` が発行され、以降のリクエストで作品が返る。モーダルの HTML は消える |
| 以後 Cookie を保持したまま `list.php?store=adt` | 4,373 件の一覧が読める |

専用の年齢確認 Cookie は無く、通常の PHP セッション (`ECSESSID`) に状態が乗る。
ポケドラの `robots.txt` はこの導線を禁じていない (禁止は `/cart/*` と `/mypage/*` のみ)。

DLsite 本体が成人向けを主力に扱うサービスであることから、成人向け作品のアフィリエイト自体は
想定されていると読める（推測）。ただし規約本文にそう書いてあるわけではない。
利用規約 第 17 条 (禁止行為) の本文は今回取得していない。**着手前に読むこと。**

二次情報 (個人ブログ。一次情報ではないので判断の根拠にはしない) では、
R18 を扱うなら年齢確認・注意書きをページ上に置くこと、露骨な画像や文言を一般向けページに出さないこと、
公式提供範囲外の画像の掲載や作品説明文の丸ごと転載は規約違反、とされている。
最後の点 (画像・説明文の転載制限) は先行調査でステラプレイヤー・kikubon について記録した制約と同種で、
**メタデータの参照とリンクに留める設計**という既存方針と整合する。

禁止コンテンツの定義 (原文ママ):

> (a) content containing, promoting, or facilitating child sexual exploitation and abuse or human trafficking;
> (b) content that infringes on another person's intellectual property rights or is otherwise unlawful;
> (c) content that discloses sensitive personal information, incites or exploits violence, or is intended to defraud the public; and
> (d) content that seeks to distribute malware, facilitate phishing, or otherwise constitutes technical abuse.

**合法な成人向けコンテンツ / ポルノは、禁止カテゴリとして名指しされていない。**

Self-Serve Subscription Agreement (<https://www.cloudflare.com/terms/>) の第 2.7 条も同様で、
禁止されるのは知的財産権侵害・違法なコンテンツ・マルウェアであり、成人向けの記述は無い。
かつて存在した「非 HTML コンテンツの配信制限」に相当する条項も、現在の本文には見当たらなかった。

| 論点 | 判定 |
|---|---|
| Workers / D1 で成人向けを扱えるか | **規約上の明示的な禁止は無い** |
| 注意点 | 禁止は「違法なコンテンツ」。日本法上適法な成人向け作品の**メタデータとリンク**を扱う限り、この条項には当たらない（推測） |
| 未確認 | 画像を自前で再配信する場合の扱い。本プロジェクトは外部 URL 参照の方針なので現時点では問題にならない |

### 3-4. 年齢確認の実務

今回 2 サイトの実装を実物で観測した。どちらも**自己申告のみ**で、身分証確認やアカウント連携は無い。

| サイト | 仕組み | サーバー側のフィルタ |
|---|---|---|
| DLsite | クライアント側 JS (`/js/adultcheck.js`) のモーダルのみ | **無し**。Cookie 無しで R18 の一覧が HTTP 200 で返る |
| ポケドラ | 自己申告モーダル → `?store=adt&age_check=1` へ遷移 → `ECSESSID` セッションに記録 | **有り**。未確認だと作品 0 件 |

自社サイトに実装する場合、日本のサービスで一般的なのは
「18歳以上ですか / 高校生を除く」の自己申告 1 枚 + Cookie 保存という、ポケドラ相当の水準（推測。
観測した 2 例からの一般化であり、法令の要求水準を調べたわけではない）。

**各ストアのアフィリエイト規約が要求する年齢確認の水準**: 今回取得した範囲では、
DLsite のアフィリエイトパートナー規約にも Amazon アソシエイト運営規約にも、
提携者サイトの年齢確認を具体的に定めた条項は見つからなかった。
Amazon 側は水準を定める代わりに「露骨な性的描写がある場合」を**参加拒否の理由**にしている。

## 4. 結論

### (a) DLsite の R18 を解禁する実利: ほぼ無い

| 指標 | 値 |
|---|---:|
| 代表 10 名の全年齢作品 | 116 件 |
| 同 R18 のみの作品 | **0 件** |
| 対象声優 1 人あたりの増加 | **+0.0 件** |
| **増加率** | **0%** |

DLsite の R18 音声には約 68,000 件の在庫があり、全年齢 (8,970 件) の 7.6 倍の規模がある。
それでも**アニメ声優の本名義に紐づく作品は 1 件も増えない。**

当時の設計書は「DLsite maniax (R18) の実利は未測定」としていた。測った結果、実利はゼロだった。
`/home/` だけを見るという現在の実装を変える理由は、DLsite に関しては見つからなかった。

補足: この結論は `keyword_creater` の完全一致で測ったもの。
別名義での出演があるかどうかは測っていないし、推測もしない。
仮にあったとしても、それを本人と結び付ける手段を本プロジェクトは持たない (別名義の原則: `docs/product.md`)。

### (b) ポケドラの BL / R18 を含める技術的な障壁

| 対象 | 障壁 | 実利 |
|---|---|---|
| **BL (911 件)** | **無し**。年齢確認不要、Cookie 不要、robots も許可。声優は本名義でタグ付き | **大きい**。斉藤壮馬は一般 45 件に対し BL 98 件。除外すると 3 分の 2 を失う |
| **オトナ向け (4,373 件)** | 小さい。自己申告 + セッション Cookie で取得可能 | **小さい**。書かれている名義がアニメ声優の本名義と交わらない (サンプル 17 名義中 0 名一致、斉藤壮馬の検索も 0 件) |
| **オトナBL (317 件)** | 同上 | **未測定**。名義の一致率を測っていない |

技術的な障壁という意味では BL はゼロ。オトナ向け 2 ストアも「技術的には」取れる。
問題は技術ではなく、(c) の運用条件と、そもそも実利が無いこと。

**BL を含めることが、年齢区分の方針変更から得られる実利のほぼ全部である。**
そして BL には年齢確認が要らない。

### (d) 設計への示唆

- **`StoreSlug` に年齢区分を持たせる必要は、DLsite については生じない。** `/home/` のままでよい
- ポケドラを追加するときは、ストア区分 (`men` / `bl` / `adt` / `adt-bl`) を作品の属性として保存する。
  `AudioWork.adult` の真偽値だけでは BL と一般を区別できないので、**区分は真偽値ではなく列挙が要る**
- 当時の `adult: boolean` と、
  「導入しないもの: …成人向け作品」という記述は、§14 の決定と食い違ったままになっている。
  本調査の結論 (DLsite R18 は実利ゼロ、ポケドラ BL は年齢確認不要) を踏まえて整理が要る
- **別名義の自動紐付けは、現時点では根拠が無い。** DLsite のクリエイター ID は全年齢の範囲で名義と 1 対 1 で、
  名義をまたぐ例は 1 件も観測されなかった。ただし手元のデータに R18 作品が無いため否定もできていない (§5)
- ポケドラ BL を入れる場合、`store` パラメータを付けて 1 声優あたり 2 リクエスト (一般 + BL) になる。
  オトナ向け 2 ストアを外せば Cookie 管理もセッション維持も不要になり、クローラーが単純なままで済む

## 5. 追加調査: DLsite のクリエイター ID は名義をまたぐか (2026-09-18 追加)

方針が「別名義も、信頼できる情報に基づくなら紐付けてよい」に変わったため、
**DLsite 自身が同一人物として扱っている事実**が取れるかを既存データで確かめた。
ネットワークは使っていない (リクエスト 0 件)。

### 5-1. 集計したデータ

`crawler/.cache/snapshots/dlsite/product-*.json` の全ファイル。

| 項目 | 値 |
|---|---:|
| スナップショット ファイル数 | 2,354 |
| 作品として読めたもの | 2,275 (残り 79 は API が `[]` を返した既知の分) |
| そのうち `age_category` が 1 (全年齢) | **2,275 = 100%** |
| `creaters.voice_by[]` のエントリ数 | 1,006 |
| 全 classification 合計のエントリ数 | 3,490 (`illust_by` 855 / `voice_by` 1,006 / `created_by` 832 / `music_by` 284 / `scenario_by` 513) |

### 5-2. 結果

| 問い | `voice_by` のみ | 全 classification |
|---|---:|---:|
| 異なり `id` 数 | 402 | 1,445 |
| 異なり `name` 数 | 402 | 1,445 |
| **(a) 同じ `id` に複数の `name`** | **0 件** | **0 件** |
| **(b) 同じ `name` に複数の `id`** | **0 件** | **0 件** |

**`id` と `name` は完全な 1 対 1 だった。代表例として挙げられる「同じ id に複数名義」のケースは 1 件も存在しない。**

ただし `id` が**人単位**の識別子であることは確認できた。
1 つの `id` が複数の classification にまたがる例が **138 件**ある。

| id | name | 役割 |
|---|---|---|
| 44399 | 古賀葵 | `voice_by` 5 件 / `music_by` 2 件 |
| 50989 | 山根綺 | `voice_by` 7 件 / `music_by` 2 件 |
| 41300 | 会沢紗弥 | `voice_by` 4 件 / `music_by` 1 件 |
| 15080 | ひづき夜宵 | `created_by` 3 件 / `illust_by` 3 件 |

つまり `id` は「声優としての ID」ではなく「クリエイターとしての ID」で、
同じ人が声も音楽もやれば 1 つの `id` にまとまる。役割はまたぐ。**名義をまたぐ例は無い。**

### 5-3. この結果の限界 (重要)

**このデータセットは、探している現象を原理的に含みえない。**

スナップショットは 2,275 件すべてが `age_category: 1` の全年齢作品である。
別名義の紐付けが問題になるのは「全年齢の本名義」と「R18 の別名義」が同じ `id` を共有する場合だが、
**キャッシュに R18 作品が 1 件も入っていない以上、その組み合わせは出現しようがない。**

したがって現時点で言えるのは次の 2 つだけ。

1. **全年齢の範囲では、`name` → `id` は曖昧さなく決まる** (402 名義すべてが 1 対 1)。
   クローラーが `id` を安定キーとして保存する設計は成り立つ
2. **「DLsite が別名義を同一人物として扱っている」という事実は、現在のデータからは確認も否定もできない**

**この結果を別名義の自動紐付けの根拠には使えない。** 根拠になるかどうかは、まだ測っていない。

### 5-4. クリエイターのプロフィールページはあるか

**声優・クリエイター個人のプロフィールページは、既存の HTML から見つからなかった。**

検索結果 HTML に出てくるクリエイターへのリンクは、すべて**名前による検索 URL** である。

```
https://www.dlsite.com/maniax/fsr/=/keyword_creater/"上田麗奈"/ana_flg/all
```

| 確認したこと | 結果 |
|---|---|
| `product.json` の数値 ID (上田麗奈 = `42968`) が検索 HTML に出るか | **出ない** (`/home/` `/maniax/` の検索結果 HTML で出現 0 回) |
| ID で引けるクリエイター URL が HTML にあるか | **無い**。クリエイターへの導線は `keyword_creater/"名前"` のみ |
| プロフィールページがあるもの | **サークルだけ**。`https://www.dlsite.com/maniax/circle/profile/=/maker_id/RG01068359.html` |
| robots.txt に関連する禁止 | `Disallow: /*/author/list/` がある。作者インデックスに相当するパスは存在するが**クロール禁止** |

副次的な発見として、検索結果には**同じ名義で他サイトを検索するリンク**が並んでいる
(`/bl/`、`/girls/`、`/garumani/`、`/maniax-touch/` それぞれへの `keyword_creater/"上田麗奈"`)。
これも名義ベースで、ID ベースではない。
DLsite の UI 上、クリエイターは「名義」で串刺しされていて、「人」では串刺しされていない。

### 5-5. 次に測るなら

`id` が名義をまたぐかを確かめるには、**R18 作品側の `voice_by[].id` を取って、
全年齢側で観測済みの 402 個の `id` と突き合わせる**必要がある。

| 障害 | 内容 |
|---|---|
| ID で作品を引く手段が無い | クリエイター ID から作品一覧を引く URL が公開 HTML に存在しない。`id` → 作品の逆引きができない |
| よって全数調査は総当たりになる | R18 音声は約 68,000 件。`Crawl-delay: 10` で 189 時間 |
| 標本調査では当たりにくい | 402 個の ID が R18 側の巨大な母集団に混ざっているかを見るので、数百件のサンプルでは 0 件が期待値になり、結論が出ない |

現実的な確認方法は 1 つだけある。
`fsr` の検索パラメータに**クリエイター ID で絞る形が存在するか**を試すこと (例: `creater_id/42968`)。
存在すれば 1 リクエストで「この ID に紐づく作品を R18 まで含めて全部出す」ことができ、
別名義があるかどうかが即座に分かる。存在しなければ、この方向の自動紐付けは断念することになる。
**コストは 1〜2 リクエスト。** 今回はリクエスト上限を既に超過しているため実施していない。
