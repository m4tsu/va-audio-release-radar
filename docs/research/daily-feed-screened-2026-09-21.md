# 対象外の判断を覚えたときの日次の往復 (2026-09-21)

読者: 日次の走行が相手サイトに出す往復を見積もる人
更新: しない。測定した日の事実として固定する
削除: 対象外の判断を覚える仕組みをやめたら

対象声優が 1 人も居ない作品の商品 ID を覚えて、翌日以降の詳細取得を省くようにした
(`src/server/queries/screened.ts`)。その前後を同じ日に 2 回続けて走らせて測った記録。

覚える前の 1 回目の実測は
[`dlsite-daily-feed-2026-09-21.md`](./dlsite-daily-feed-2026-09-21.md) と
[`audible-daily-feed-2026-09-21.md`](./audible-daily-feed-2026-09-21.md) にある。

---

## 1. 条件

- 手元の D1 と dev サーバーに対して `crawler/daily.ts --store <store> --no-snapshot` を 2 回続けて実行
- 1 回目と 2 回目の間に一覧の中身は変わっていない (同じ日に続けて走らせた)
- 走行前の `screened_store_products` は 0 件
- 走行前の `store_listings` は DLsite 992 件 / Audible 2,081 件 (いずれも声優起点で集めたもの)
- **同じ日の別の走行なので、下の「1 回目」の数字は
  [`dlsite-daily-feed-2026-09-21.md`](./dlsite-daily-feed-2026-09-21.md) や
  [`audible-daily-feed-2026-09-21.md`](./audible-daily-feed-2026-09-21.md) と一致しない。**
  一覧の中身が数時間で入れ替わるため。ここで見たいのは 1 回目と 2 回目の差なので、
  同じ条件で続けて取ったこの 2 つを並べる

## 2. DLsite

| | 1 回目 | 2 回目 |
|---|---:|---:|
| 一覧に出た作品 | 60 | 60 |
| 詳細 (`product.json`) を引いた作品 | **59** | **0** |
| 保存した作品 | 16 | 0 |
| 対象声優が居ないとして捨てた作品 | 43 | 0 |
| 相手サイトへの往復 (一覧 + 詳細) | **61** | **2** |

1 回目が覚えた 43 件と、保存された 16 件が既知になり、2 回目は一覧 2 ページを引いただけで終わった。
2 回目の所要は **10 秒** (`crawl_runs` の `started_at` 11:23:02 → `finished_at` 11:23:12)。

**1 回目の所要はこの測定では取れていない。** 同じ日の流し直しは `runId` が同じで
`crawl_runs` の行を上書きするため、2 回目で消えた。61 往復ぶんの所要は
[`dlsite-daily-feed-2026-09-21.md`](./dlsite-daily-feed-2026-09-21.md) の 10 分 0 秒が同じ形である。

**Audible の往復は変わらない。** 一覧にナレーターと配信日が載るので元から作品ページを引いておらず、
覚えることで減るものが無い。減るのは取り込みへ送る件数だけ。

## 4. ここから読めること

- **詳細を引くストア (DLsite・ポケドラ) では、定常状態の往復が一覧のページ数に近づく。**
  61 → 2 は「一覧が 1 件も動かなかった日」の値で、実際には新作のぶんだけ詳細が増える。
  新作の量は各ストアの調査にある
- **声優の辞書が増えた翌日だけ往復が増える。** 覚えたことを全部捨てるため
  (`src/server/queries/screened.ts` の `clearScreened`)。ただし 1 回目と同じ数には戻らない。
  保存済みの作品は `store_listings` に残って既知のままなので、引き直すのは
  「一覧に出た作品 − 保存済み」
- **(推測)** 定常状態の往復は「一覧のページ数 + 1 日あたりの新作数」に近いはずだが、
  日をまたいだ観測はしていない
