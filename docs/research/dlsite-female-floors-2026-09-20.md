## 2. 検索 URL が女性向けのフロアでも使えることの実測

`/home/` 用の形からパスの先頭を差し替えただけの URL が HTTP 200 を返し、
埋め込み JSON の `pager.count` も一覧の `li[data-list_item_product_id]` も同じ位置にあった。
`dd.work_name a[title]` / `dd.maker_name > a` / `dd.work_price_wrap` /
`div.work_category type_SOU` / `thumb-with-ng-filter-block` も同じで、既存のパーサーがそのまま当たる。

`/garumani/` は年齢の指定なしで全年齢だけが返り、`/girls/` と `/bl/` は
`age_category[0]/general` を足したときだけ全年齢だけが返った。

並び順は `/home/` と同じく `order/release_d` (新しい順) と `order/release` (古い順) が効く。
`/garumani/` の斉藤壮馬 (総件数 52) で両方を取ったところ、新しい順 30 件と古い順 30 件の
和集合がちょうど 52 件になり、重複は 8 件だった。**総件数が 60 以下なら 2 回で全件取れる**という
`/home/` での性質がそのまま成り立つ。

## 5. 同じ作品が両方に出るか、ID は衝突するか

**作品 ID は DLsite 全体で 1 つの体系になっていて、フロアをまたいでも同じ ID である。衝突はしない。**

- 同じ作品が複数のフロアに出る例がある。`RJ01088408` は `/home/` と `/girls/` の両方に出て、ID は同一
- `product.json` の `site_id` はリクエストしたフロアではなく**作品が属するフロア**を返す。
  `RJ01088408` の `site_id` は `girls` で、`/home/` の検索結果に出ていても `home` にはならない
- ローカル D1 の `store_listings` は既にこの性質を反映している。`store_slug = 'dlsite'` の行の
  `store_section` は `home` 717 / `girls` 46 / `bl` 1 / `pro` 3 / `soft` 4 / 未設定 220 (2026-09-20 時点)。
  **`/home/` の検索だけで `girls` と `bl` の作品が既に入っている**
- `BJ` で始まる行は 1 件も無い。`crawler/.cache/snapshots/dlsite/search-*.html`
  (2026-09-18 に保存した `/home/` の声優検索。2026-09-20 時点で 35 ファイル) に出る作品 ID は
  異なり 200 件で、内訳は `RJ` 198 件と `VJ` 2 件。`BJ` は 0 件

したがって取りこぼしているのは **`BJ` (商業) の女性向け全年齢音声作品**であり、
同人の女性向け全年齢作品 (`/girls/` と `/bl/` の全年齢) は、測定した範囲では
`/home/` から既に取れている。
ただし各フロアで作品 ID を数えたのは 1 ページ目 30 件と声優 10 名の検索結果だけで、
`/garumani/` の 1,053 件すべてが `BJ` であることを確かめたわけではない。

**未確認**: `/girls/` の全年齢 939 件と `/bl/` の全年齢 91 件が、`/home/` の 8,981 件に
すべて含まれるか。確かめたのは `RJ01088408` の 1 件と、声優 5 名の件数が
`/home/` を超えなかったことだけである。

## 6. R18 を取り込み時に除外できるか

**できる。手がかりは 2 つあり、どちらも既存の実装で読める。**

| 手がかり | 場所 | 値 |
|---|---|---|
| フロアの選択 | 検索 URL | `/garumani/` は全年齢だけのフロア。`/girls/` と `/bl/` は `age_category[0]/general` で絞る |
| 作品単位の年齢区分 | `product.json` の `age_category` | 1 が全年齢。`crawler/adapters/dlsite.ts` の `toAgeRating()` がそのまま使える |

取得した `product.json` 7 件は `RJ01088408` を含めてすべて `age_category: 1`
(`age_category_string: "general"`) だった。`/garumani/` から選んだ 6 件も全部 1 で、
全年齢フロアという表示と食い違わなかった。

女性向けかどうかは `product.json` の `sex_category` でも分かる。取得した
`/garumani/` の作品と `RJ01088408` はすべて `sex_category: 2` だった。

## 7. ストア区分として何が返るか

`product.json` の `site_id` は、フロア名 (`garumani`) ではなく作品の所属を返す。実測した値:

| workno | `site_id` | `work_category` | `sex_category` | 出どころ |
|---|---|---|---:|---|
| `BJ02860641` | `bldrama` | `books` | 2 | `/garumani/` 斉藤壮馬 |
| `BJ02889107` | `bldrama` | `books` | 2 | `/garumani/` 全体の 1 件目 |
| `BJ02917258` | `girlsdrama` | `books` | 2 | `/garumani/` 全体の 30 件目 |
| `RJ01088408` | `girls` | `doujin` | 2 | `/girls/` 全年齢、`/home/` の両方 |

`robots.txt` の `Sitemap:` 行に `girlspro` と `blpro` があるので、`/garumani/` が
`girlspro` / `blpro` の作品も返す可能性がある。**未確認** (今回の実測では出なかった)。

`product.json` はフロアに依らず `/home/api/=/product.json?workno=` で引けた。
`BJ` の作品も `RJ` と同じく 1 件ずつ引ける。

## 8. 日次クロールに足したときの見積もり

`/garumani/` の音声カテゴリをキーワード無し・新しい順で引いた 1 ページ目 30 件のうち
5 件の `regist_date` を `product.json` で確かめた。

| 一覧の位置 | workno | `regist_date` | `is_reserve_work` |
|---:|---|---|---|
| 1 | `BJ02889107` | 2026-10-28 00:00:00 | **true** |
| 6 | `BJ03002580` | 2026-09-17 00:00:00 | false |
| 10 | `BJ02945716` | 2026-09-11 16:00:00 | false |
| 11 | `BJ02917273` | 2026-09-05 00:00:00 | false |
| 30 | `BJ02917258` | 2026-08-22 00:00:00 | false |

**6 件目〜30 件目の 25 件が 2026-08-22 〜 2026-09-17 の 26 日ぶんに収まる。
1 日あたり約 0.96 件。** `/home/` の 6.4 件/日 (2026-09-19 実測) の約 6.7 分の 1 である。

2 件目〜5 件目は測っていないので、そこに発売済みの作品が混じっていれば
同じ 26 日の窓に入る件数が増える。**0.96 件/日 は下限**として読む。

1 ページ 30 件と最小間隔 10 秒 (`rateLimitFor()` の `dlsite`) から:

対象声優の人数は `crawler/actors.generated.json` の要素数 (2026-09-20 時点で 2,567)。

| | リクエスト | 所要 |
|---|---:|---:|
| 日次 (一覧 1 + 新規 ID の `product.json` 約 1) | 約 2 件/日 | 約 20 秒/日 |
| 初回だけ (一覧 1 + 30 件すべての `product.json`) | 31 件 | 約 5.2 分 |
| 初期構築を声優起点でやる場合 (対象声優 2,567 名、1 名 1 ページ) | 2,567 件 + 新規作品の `product.json` | 約 7.1 時間 + 詳細分 |

日次の増分は 1 日 20 秒で、既存の DLsite の日次 (一覧 1 + 新作 6.4 件 = 約 7.4 件、約 74 秒) に
上乗せしても分の単位に収まる。初期構築だけは `/home/` と同じ性質の問題で、
声優を分割して複数日に分ける必要がある。

**`/garumani/` の新着一覧には発売日が未来の予約作品が出る。** 1 件目の `regist_date` は
2026-10-28 で、測定日 (2026-09-20) より 38 日先だった。`/home/` では 2026-09-19 の観測で
予約作品が 0 件だったので、ここは `/home/` と挙動が違う。
判定は `product.json` の `is_reserve_work` (この作品は `true`) で機械的にできる。
一覧 HTML には「予約」の文字が 1 度も出ないので、一覧からは見分けられない。

## 9. 判定

この文書は測定の記録であって決定記録ではない。ここに書くのは測定から言えることまでで、
取るフロアを変える決定そのものは `docs/decisions/` に別途書く。

**測定から言えるのは「`/garumani/` (女性向け 全年齢) を取る価値があり、
`/girls/` と `/bl/` には無い」ということ。**

`/garumani/` を取る価値があると言える理由:

- 代表 10 名の作品が 116 件から 182 件になる (**+66 件、+57%**)。増分はすべて `/home/` に無い作品
- 増分は 10 名のうち 3 名に集中する。斉藤壮馬は `/home/` 1 件に対し 2 フロアの和で 53 件になり、
  **53 倍**である。今の `/home/` だけでは、この人をフォローしても作品がほぼ出ない
- フロア全体が全年齢なので、R18 を取り込む判断をしないまま足せる
  ([`0003-no-r18-keep-bl.md`](../decisions/0003-no-r18-keep-bl.md) の範囲に収まる)
- robots.txt はこのフロアを禁じていない。検索 URL の形もセレクタも `/home/` と同じで、
  既存のパーサーがそのまま当たる
- 日次のコストは 1 日 2 リクエスト・20 秒

`/girls/` と `/bl/` に価値が無いと言える理由:

- 全年齢に絞ると `/home/` と重なる。声優 5 名の測定で `/home/` を超えた件数が 1 件も無く、
  唯一出た `RJ01088408` は `/home/` にも同じ ID で出ている
- 全年齢以外は R18 で、対象外

取り込む場合にやること (実装は別に切る。この一覧は測定から出る作業の洗い出し):

1. **アダプタ**: `crawler/adapters/dlsite.ts` の検索 URL を `/home/` 固定から
   フロアを受け取る形にし、1 声優につき `/home/` と `/garumani/` の 2 フロアを引く。
   並び順 2 回の和集合を取る既存の仕組みはフロアごとにそのまま使える
2. **ストア区分**: `storeSection` は今までどおり `product.json` の `site_id` をそのまま入れる。
   `bldrama` / `girlsdrama` という値が新しく入る。`storeSection` の許可集合はコードに無く
   (`src/server/db/schema.ts` は素の text、`src/domain/types.ts` は任意の文字列)、
   足す作業は発生しない
3. **年齢区分の判定**: `toAgeRating()` は変えない。`age_category` が 1 以外なら捨てる既存の経路で足りる
4. **日次クロールへの追加**: `/garumani/` の新着一覧を `/home/` と並べて引く。
   発売日が未来の作品を画面でどう扱うかは既に決まっている
   (`src/app/components/follow-feed.tsx` の `freshness === "upcoming"` の段)。
   決まっていないのは **upcoming に何日先まで載せるかの上限**だけで、
   `/garumani/` で観測した予約作品は測定日の 38 日先だった
5. **重複**: 作品 ID はフロアをまたいで同一なので、同じ ID を 2 フロアから拾ったときに
   1 行にまとまることを確かめる
6. **コメントの訂正**: `crawler/adapters/dlsite.ts` の `DLSITE_HOME_SITE_ID` に付いた
   「全年齢サイトの `site_id`。R18 サイトは `maniax` になる」は、`site_id` が
   リクエストしたフロアではなく作品の所属を返すという実測と食い違う
