読者: ポケドラの日次クロールを実装する人。新着一覧に何が載るかを確かめたい人
更新: しない (日付つきの測定。数字を書き換えない)
削除: 参照する文書が無くなったら

[`new-release-feeds-2026-09-19.md`](./new-release-feeds-2026-09-19.md) のポケドラの節は、
当時 pokedora.com へアクセスできなかったため保存物だけで書かれており、一覧の件数・項目・
ページ送り・新作数がすべて未検証だった。それを実際に引いて確かめた記録。

DB には書き込んでいない。コードも変更していない。
robots.txt の引用と、そこから導いた使ってよい形は [`docs/stores/pokedora.md`](../stores/pokedora.md) にある。

## 0. 調査方法とリクエスト実績

- 外部へのリクエストは **8 件**。**すべて `pokedora.com`**
- 取得は `crawler/lib/fetch.ts` の `fetchText` を通した。UA は `userAgentFor()` の既定 (ブラウザ相当)、
  間隔は `rateLimitFor()` の `pokedora` の値
- **JS は実行していない。** ブラウザを立ち上げていないので、一覧の無限スクロールが
  追加で何を読むかは見ていない
- 2 つの Node プロセスに分けて順に実行した。重ねて走らせていないので、実効間隔は設定どおり

| 取得先 | 件数 |
|---|---|
| `/robots.txt` | 1 |
| `list.php?order=1&store=men` (`pageno` 1 と 2) | 2 |
| `list.php?order=1&store=bl` (`pageno` 1) | 1 |
| `detail.php?product_id=151971` / `=151983` | 2 |
| `sitemap_products_1.xml.gz` / `_2.xml.gz` | 2 |
| **合計** | **8** |

2 プロセス目の 4 リクエストの所要は 5.11 / 4.82 / 4.29 / 5.00 秒で、設定した間隔とほぼ一致していた。
相手側で絞られてはいない。**間隔の値そのものは `crawler/lib/fetch.ts` が持つ。**

## 1. 一覧は引ける。ただし 1 ページ 15 件

引いた URL (`{store}` は `men` と `bl`、`{n}` は 1 と 2):

```
https://pokedora.com/products/list.php?mode=search&name=&xfp=0&genre_tag_id=0&order=1&store={store}&disp_number=100&pageno={n}
```

3 本とも **HTTP 200**。

| | 一般 (`store=men`) | BL (`store=bl`) |
|---|---|---|
| 総件数 (`div.search_count`) | 1,365 件 | 911 件 |
| 1 ページの件数 | **15** | **15** |
| 最終ページ (ページャの「最後」) | 91 | 61 |

- **`disp_number` は効かない。** `100` を付けても 15 件のまま返る。`list.php` のフォームには
  `disp_number` の `select` が無い (`/tags/` には 30 / 50 / 100 の `select` がある)。
  91 = ceil(1365 ÷ 15)、61 = ceil(911 ÷ 15) で、総件数とも一致する
- **`pageno` は効く。** `pageno=2` の `div.search_count` は `1,365件中　16 - 30件目` で、
  1 ページ目と重複する商品は無かった
- ページャは `<a onclick="$('#p_pageno').val(2); $('#search_form_parts').submit();">` の形で、
  `href` を持たない。ページ番号は onclick の文字列から読むか、`pageno` を自分で組み立てる
- `<title>` は `… 検索結果page.1 | ポケットドラマCD(ポケドラ)` の形で、要求したページ番号が入る

## 2. 一覧に出る項目 / 出ない項目

観測は 45 件 (一般 30 / BL 15)。セレクタは [`docs/stores/pokedora.md`](../stores/pokedora.md) にある。

| 項目 | 45 件中 | 備考 |
|---|---|---|
| 商品 ID | 45 | |
| タイトル | 45 | `title` 属性が完全なタイトル。末尾の `【出演声優：…】` は主要キャストのみ |
| 商品カテゴリ | 45 | |
| 出演声優 (名前 + `tag_id`) | 45 | **2 名まで** |
| 価格 | 35 | 割引中の 10 件は `span.normal_price` を持たない |
| 4 ストアの件数内訳 | 45 | ページごとに 1 つ。タグページと同じ `ul.category_tab` |
| **発売日 / 配信日** | **0** | |

- **出演声優は 2 名で打ち切られる。** タグページと同じ。`product_id=151983` の一覧の表示は 2 名だが、
  同じ商品の詳細ページの `<meta name="keywords">` には 14 名が並ぶ
- **割引中の商品は価格のセレクタが変わる。** `span.normal_price` ではなく
  `span.individual_price` (割引後) + `span.discount_rate` + `span.basic_price` (割引前) になる。
  価格は持たない ([`decisions/0008`](../decisions/0008-no-price-no-availability.md)) ので実害は無いが、
  `normal_price` の有無を「商品かどうか」の判定に使うと 10/45 を落とす
- カテゴリの `span` には `NEW` / `割引` / `特典あり` のバッジが商品カテゴリと同じクラスで混ざる。
  カテゴリ名を取るには `product_catgory_el-new` などの修飾クラスが付いたものを除く必要がある

## 5. 新着順の基準はストアで違う

各商品の sitemap の `lastmod` を並べた (sitemap に無いものは `-`)。

| 並び順 | 一般 (`store=men`) の `lastmod` | BL (`store=bl`) の `lastmod` |
|---|---|---|
| 1〜5 | - / - / 09-14 / 09-14 / 09-14 | - / 08-05 / 09-04 / 09-02 / 09-02 |
| 6〜10 | 09-14 / 09-14 / 09-14 / 09-14 / 09-14 | 09-02 / 09-02 / 08-27 / 09-11 / 08-26 |
| 11〜15 | 09-14 / 09-14 / 09-03 / 09-03 / 09-03 | 08-26 / 09-09 / 08-21 / 08-21 / 08-20 |
| 16〜30 | 09-03 ×4 / 08-28 ×2 / 08-25 / 08-24 ×3 / 08-21 / 08-24 ×2 / 08-19 ×2 | (引いていない) |

- **一般は `lastmod` の降順とほぼ一致する。** 30 件のうち降順が崩れるのは 1 か所だけ
  (26 番目の 08-21 が 27 番目の 08-24 より古い)
- **BL は一致しない。** 2 番目の `product_id=148638` の `lastmod` は 2026-08-05 で、
  4 番目の 151195 (09-02) より 1 か月古い。逆転は 14 件中 3 か所
- `product_id` の降順とも一致しない。BL の並びは 151983 / 148638 / 151574 / 151195 / 151185 / 151340 / …

**`order=1` が並べている日付は、この測定では特定できなかった。**
`lastmod` でも `product_id` でもない、ストア側が持つ日付 (配信開始日など) と考えられる (推測)。

## 6. 1 日あたりの新作数

日付の項目が無いので、3 通りの測り方を並べる。どれも別のものを測っている。

### 6.1 `lastmod` の幅で割る

一覧に出た商品のうち sitemap に `lastmod` を持つものについて、件数 ÷ (最大 − 最小) 日。

| ストア | 件数 | `lastmod` の幅 | 1 日あたり |
|---|---|---|---|
| 一般 (1〜30 件目) | 28 | 2026-08-19 〜 2026-09-14 (26 日) | **1.08 件** |
| BL (1〜15 件目) | 14 | 2026-08-05 〜 2026-09-11 (37 日) | **0.38 件** |
| **合計** | | | **1.46 件** |

両端を含む件数を幅で割っているので、区間の数で割るより大きめに出る。見積もりは多い側に倒れる。
**BL は 5 節のとおり並びが `lastmod` と一致しないので、この行は「新着 15 件の `lastmod` が
37 日ぶんに散っている」以上の意味を持たない。**

### 6.2 sitemap に無い商品を数える

`product_id` は単調増加で割り当てられているので、sitemap の最大 151871 より大きい ID は
sitemap 生成後に採番されたものである。

一覧に出た 45 件のうち該当するのは **3 件** (一般 151932 / 151971、BL 151983)。
sitemap の `lastmod` の最大が 2026-09-14 なので、生成はそれ以降。取得日 2026-09-21 との差は
最大 7 日で、**3 件 ÷ 7 日 = 0.43 件/日**が下限側の値になる。

### 6.3 ストアの件数表示の差

`ul.category_tab` の 4 ストアの件数内訳を、2026-09-18 の測定
([`adult-scope-2026-09-18.md`](./adult-scope-2026-09-18.md)) と並べる。

| ストア | 2026-09-18 | 2026-09-21 | 差 |
|---|---|---|---|
| 一般 | 1,366 | **1,365** | −1 |
| BL | 911 | **911** | 0 |
| オトナ向け | 4,373 | **4,373** | 0 |
| オトナBL | 317 | **317** | 0 |

**3 日で純減 1 件。** 追加と削除の差なので追加数そのものではない。
6.2 で 3 件増えていることと合わせると、同じ 3 日間に 4 件前後が一覧から消えたことになる。

### 6.4 結論

**一般 + BL で 1 日あたり 1〜2 件。** 3 通りの測り方が 0.43 / 1.46 と、件数表示の純減 (−1) に
挟まれている。[`new-release-feeds-2026-09-19.md`](./new-release-feeds-2026-09-19.md) が
保存物から立てた推測「20〜25 件」とは**桁が 1 つ違う**。

1 日 1〜2 件なので、**日次で引くのは各ストアの 1 ページ目 (15 件) だけでよい。**
一般の 1 ページ目 15 件は `lastmod` 2026-09-03 以降で、取得日との差は 18 日ある。
BL は並びが `lastmod` と一致しないので日数では言えないが、15 件の `lastmod` は
2026-08-05 まで遡っている。

日次のリクエストは **2 件** (一般と BL の 1 ページ目) + 新しく見つけた商品の詳細。

## 7. その他の確認

- **`store=men` と `store=bl` に重複は無かった。** 観測した 45 件の `product_id` に重なりは 0
- **未来の配信日を持つ商品は新着順の先頭には来ていない。** タイトルに
  `《配信開始は2026年11月6日11:00》` を持つ 151340 は BL の 6 番目、
  `《配信開始は2026年11月25日0:00》` を持つ 150548 は 15 番目だった。
  一般の 30 件にはこの形のタイトルが無い
- サイトが自分で置いている「#新規配信順一覧」という人気検索ワードのリンク先は
  `list.php?order=2&…store=bl` で、**`order` の `select` が `2` に付けているラベルは「古い順」**である。
  どちらが正しいかはこの測定では決められない

## 8. この測定で分からなかったこと

- **`order=1` が並べている日付の正体。** `lastmod` でも `product_id` でもない (5 節)
- **「NEW」バッジが何日間付くか。** 一般 21 件 / BL 3 件という数字を日数に直せない
- **1 ページ目に出ない新商品があるか。** 15 件より深いページは一般の 2 ページ目しか引いていない
- **一覧から商品が消える条件。** 6.3 の純減 1 件が、非公開化なのか別ストアへの移動なのかは見ていない
- **無限スクロール (`section.autopager`) が JS で何を読むか。** ブラウザを立ち上げていない
