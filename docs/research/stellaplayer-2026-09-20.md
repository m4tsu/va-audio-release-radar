## 1. robots.txt と利用規約

`/robots.txt` と `/sitemap.xml` はどちらも **HTTP 404**、`/terms` は HTTP 200 だった (2026-09-20)。
**引用と、そこから導いた使ってよい形は [`docs/stores/stellaplayer.md`](../stores/stellaplayer.md) にある。**
ここには測定だけを置く。

## 2. ページの作りと、HTTP だけで取れる経路

Next.js の pages router。**サーバーで描いているのは 4 経路だけ**で、残りは静的書き出し
(`__NEXT_DATA__` の `nextExport: true`、`pageProps` が空) である。

| 経路 | サーバーで描くか | HTTP だけで取れるもの |
|---|:--:|---|
| `/general` `/bl` `/girls` | **描く** (`gssp: true`) | 新着 10 件、予約中、ランキング 5 件、バナー、お知らせ |
| `/product/{id}` | **描く** (`gssp: true`) | 商品 1 件の全項目 (§4) |
| `/` | 描かない | なし。トップの `pageProps` は空 |
| `/archive` | 描かない | **なし。** 一覧も総件数もクライアント側の取得で入る |
| `/terms` | 描かない | 本文は HTML に含まれる |

**`/archive` は 2026-09-18 の調査と同じで、HTTP 取得だけでは結果が読めない。**
`?top_category=GENERAL` を付けても `pageProps` は `{}` のままだった。

### 商品が無い ID は 404 ではない

`/product/1300` `/product/2500` `/product/2900` は **HTTP 200 を返し、`product` が `null`** になる。
HTML の大きさも 321,667 バイトで 3 件とも同じだった。ステータスコードで存在を判定できない。

### 一覧に出る項目と、出ない項目

## 5. 商品の総数と ID の範囲

`/product/{id}` を 17 個の ID で引いた結果 (1, 2, 100, 300, 500, 700, 900, 1100, 1300, 1500, 1700,
1900, 2100, 2300, 2500, 2700, 2900)。

- **確認できた最小の ID は 1** (`幼馴染の彼 白ルート`、`release_schedule` 2011-09-23)
- **確認できた最大の ID は 2850** (`/girls` の予約中、`release_schedule` 2026-10-30)。
  2900 は `product: null` だった
- 1〜2850 の範囲で引いた 16 個のうち **14 個に商品があった (87.5%)**。null は 1300 と 2500

**総数の点推定は 2850 × 0.875 = 約 2,500 件。** 標本が 16 個しかないので、割合の 95% 信頼区間
(Wilson) は 64%〜97%、**総数にすると 1,820〜2,750 件**の幅がある。
確定値は `/archive` の背後にある経路でしか取れず、この調査では叩いていない (§8)。

## 6. 全商品を 1 巡するコスト

一覧も sitemap も無いので、**1 巡は「ID を 1 から最大まで順に引く」ことになる**。
1 リクエスト 1 商品で、1 ページあたりの件数という概念が無い。

| 段階 | リクエスト数 | 所要 (5.0 秒/リクエスト) |
|---|---|---|
| 全件 1 巡 (ID 1〜2850) | 2,850 | **3 時間 58 分** |
| 日次 (カテゴリトップ 3 枚 + その日の新着) | 3 + 0.62 ≒ 4 | **20 秒** |

**GitHub Actions のジョブ時間上限 6 時間には収まる**
([`new-release-feeds-2026-09-19.md`](./new-release-feeds-2026-09-19.md) と同じ上限を使った)。
ただし初期構築は Actions の外で回す決定になっている
([`decisions/0007`](../decisions/0007-daily-crawl-from-store-feeds.md))。

## 7. 対象声優との重なり

- **母数**: `crawler/actors.generated.json` の **2,567 人** (2026-09-20 時点のファイル)
- **照合方法**: 商品ページの `creators[]` のうち `creator_group_id: "1"` の `name` を
  `src/domain/normalize.ts` の `normalizeName` で正規化し、対象声優の `canonicalName` と
  `aliases[].name` を同じ関数で正規化した集合に含まれるかを見た。類似度も LLM も使っていない

| 標本 | 商品 | 延べ出演 | 異なり出演者名 | 対象声優に一致 | 対象声優を含む商品 |
|---|---|---|---|---|---|
| 新着一覧由来の 14 件 | 14 | 81 | 63 | **41** | **8 / 14 (57%)** |
| ID を等間隔に引いた 14 件 | 14 | 17 | 15 | **2** | **1 / 14 (7%)** |
| 合計 (重複を除く) | 28 | 98 | 77 | **43** | 9 / 28 |

**当たりはカテゴリで完全に分かれた。**

| `top_category` / `category` | 商品 | 延べ出演 | うち対象声優 |
|---|---|---|---|
| GENERAL / ドラマ | 5 | 65 | 42 |
| BL / ドラマ | 5 | 12 | 11 |
| GIRLS / シチュエーション | 16 | 17 | **0** |
| GIRLS / ドラマ | 1 | 4 | **0** |
| GENERAL / 歌・サントラ | 1 | 0 | 0 |

- ドラマ CD は 1 商品に 2〜20 名が出て、その大半が対象声優に当たる
- **シチュエーション CD は 1 商品 1 名で、16 件 17 名が 1 人も当たらなかった。**
  当たらなかった名前の例: 十利須我里、深川緑、二枚貝ほっき、九財翼、早川凛太
- ID を等間隔に引いた 14 件のうち **12 件が GIRLS / シチュエーション**だった。
  カタログの大半がこの層である (推測。標本 14 件からの外挿)

**back catalog のうち対象声優を含む商品の点推定は 2,500 × 7% ≒ 175 件。**
標本 14 件なので 95% 信頼区間 (Wilson) は 1.3%〜31%、**32〜786 件**の幅がある。

## 8. 未確認の項目

- **商品の総数の確定値。** `/archive` の背後にある取得経路 (別ホストの GraphQL) を叩いていないため。
  声優名での絞り込みができるか、絞り込みのパラメータ名も同じ理由で未確認
- **新着一覧が 10 件より多く取れるか。** サーバーで描く 3 ページの問い合わせは引数が固定で、
  HTML 側にページ送りの手段が見えない
- **成人向け商品が HTTP 取得だけで見えるか。** `is_adult` というフィールドはあるが、
  取得した 28 件はすべて `false` だった。年齢確認の導線があるかは確認していない
- **`sale_status` の全語彙。** 観測は `ON_SALE` と `PREORDER` の 2 つだけ。販売終了を表す値があるかは不明
- **`product: null` の理由。** 欠番なのか、非公開なのか、削除なのかを区別する材料が無い
- **作品の重複。** DLsite やポケットドラマ CD に同じ作品があるかは照合していない
- **アフィリエイトプログラム。** このホストの取得物には見当たらなかった
