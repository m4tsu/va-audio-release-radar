### 既存カタログとの照合

ローカル D1 の `audio_works` / `store_listings` / `audio_credits` を読み取り専用で引いた。

1. **タイトル**: 双方を `normalizeName` で正規化して完全一致、および
   ステラプレイヤー側から `(…)` `【…】` `《…》` を落とした芯での包含 (8 文字未満の芯は捨てる)

3. 候補が出た商品は、タイトルと出演者を並べて**同じ作品かを 1 件ずつ判定した**

タイトルだけでは取りこぼす (`ドラマCD「アリドロ」` と `アリドロ【出演声優：…】` は
どちらも相手を含まない)。出演者だけでは同じ声優の別作品が当たる。両方を出してから目で決めている。

したがって次の 2 つを切り分ける材料は、この取得の範囲には無い。

- このホストに R18 の商品が無く、`is_adult` が使われていないだけ
- `is_adult` が別の意味 (たとえば別の入口にある商品の印) で、内容の区分には対応していない

**どちらであっても `is_adult: false` を「全年齢」と読み替える根拠にはならない。**
上の 5 件はいずれも GIRLS / シチュエーションで、**対象声優は 1 人も含まない**。
BL / ドラマ側で観測した `オメガバース` の 4 件はすべて対象声優を含み、題名に性行為の語は無い。

観測した `top_category` は `GENERAL` / `BL` / `GIRLS` の 3 つだけで、成人向けの区分は現れなかった。

## 6. ページの作り (前の測定で引いていなかった 2 経路)

| 経路 | `__NEXT_DATA__` の `page` | 描き方 | HTTP だけで取れるもの |
|---|---|---|---|
| `/maker/[maker]` | `/maker/[maker]` | `nextExport: true` | **なし。** `pageProps` が空 |
| `/ranking` | `/ranking` | `nextExport: true` | **なし。** `pageProps` が空 |

`/maker/83` (`brand.id` が `83` のレーベル) は HTTP 200 を返し、`page` も
`/maker/[maker]` に解決していて 404 ではない。それでも中身はクライアント側の取得で入る。
**ID を 1 から舐めるより安い 1 巡の経路は、この 2 つには無い。**

**静的に書き出されたページの `__NEXT_DATA__` の script タグには `crossorigin=""` が付く。**
サーバーで描くページ (`/product/{id}`、カテゴリトップ) には付かない。
属性を決め打ちした正規表現で取り出すと、静的ページだけ「タグが無い」と誤る。

## 7. その他の観測

- **版違い**: `editionGroup.activeEditions[]` が空でない商品は 103 件中 **48 件**
- **`sale_status`**: 観測したのは `ON_SALE` と `PREORDER` の 2 つだけ (103 件)。
  標本 1 の 73 件はすべて `ON_SALE` で、**販売終了を表す値は現れなかった**
- **`category`**: 観測したのは `ドラマ` / `シチュエーション` / `歌・サントラ` の 3 つ

## 8. この測定で分からなかったこと

- **商品の総数の確定値。** 推定の幅は 2,047〜2,504 件ある
- **`is_adult` が何を表しているか。** 103 件で `true` を 1 件も観測していない (上限 3.6%)。
  R18 の商品が無いのか、フラグが内容の区分に対応していないのかを分ける材料が無い
- **標本 2 の 30 件は 1 日の一覧から取った。** 品揃えの季節変動は測っていない
- **重複の判定はローカル D1 の 5,224 行に対して行った。** その中身は
  [`decisions/0010`](../decisions/0010-back-catalog-is-what-was-fetched.md) の言う
  「取得できた作品」で、各ストアの全件ではない。既存カタログ側の取りこぼしは重複を小さく見せる
- **純増 0 件は標本 10 件からの推定。** 対象声優を含む商品に条件づけた 95% 上限は 88 件ある
