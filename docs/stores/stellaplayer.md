# ステラプレイヤー (www.stellaplayer.jp)

読者: ステラプレイヤーへアクセスする前の人。取り込みを実装する前の人
更新: robots.txt と利用規約を取り直したら (差分が無くても最終確認日を更新する)。サイトの作りが変わったと分かったら
削除: ステラプレイヤーを対応ストアから外したら

**取り込みは未実装。** アダプタは無い。外部アクセスは `crawler/lib/fetch.ts` を通す。
共通の原則は [`README.md`](./README.md)。

運営は株式会社ステラワース。女性向けを中心にした音声作品の直販。
サイトは Next.js の pages router で、サーバーで描くページは `__NEXT_DATA__` に構造化された JSON を持つ。
どの経路をサーバーが描き、何が取れるかは
[`docs/research/stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の
「ページの作りと、HTTP だけで取れる経路」「新着一覧」「商品ページから取れる項目 / 取れない項目」。

**追加するかどうかはまだ決まっていない。** このファイルはアクセスする前に読む制約を集めたもので、
採否の決定記録は無い。決まったら `docs/decisions/` に 1 ファイル増える。

## robots.txt

**最終確認日: 2026-09-20** (`https://www.stellaplayer.jp/robots.txt`)。

**存在しない。HTTP 404 が返る。** `https://www.stellaplayer.jp/sitemap.xml` も HTTP 404 である。

ここから導けること:

- 禁止パスの宣言が無い → 字面で照合する対象が無い。どのパスも robots では禁じられていない
- `Crawl-delay` の宣言が無い → 間隔はこちらで決める (「レート間隔」)
- sitemap が無い → **全商品の URL を列挙する手段がこのホストに無い** (「既知の落とし穴」)

### 利用規約 (`https://www.stellaplayer.jp/terms`、最終確認日 2026-09-20)

**第 10 条 (禁止事項) ① が並べる 12 の行為に、情報解析・自動取得・クローリングを名指しするものは無い。**
audiobook.jp が置いている「当社の事前の許可なく、情報解析…をする行為」に当たる条項が無い、という意味である
([`README.md`](./README.md) の表で audiobook.jp が未着手なのはその条項があるため)。

取得の仕方に関係しうるのは同条の次の 5 つ。**後ろの 2 つは包括条項で、字面では線が引けない。**
負荷をかけない側に倒す理由がここにある。

> 第三者の設備又は本サービス用設備(当社が本サービスを提供するために用意する通信設備、電子計算機、
> その他の機器およびソフトウェアをいい、以下同様とします)に無権限でアクセスし、又はその利用もしくは
> 運営に支障を与える行為(与えるおそれのある行為を含む)。

> 当社もしくは第三者の著作権、商標権等の知的財産権を侵害する行為、又は侵害するおそれのある行為

> 当社が許可した利用形態を超えて営利を目的として本サービスを利用する行為。

> 記各号の他、法令、本利用規約及びこれに付随する規約等又は公序良俗に違反する行為、
> 本サービスの運営を妨害する行為、当社の信用を毀損し、又は当社の財産を侵害する行為、
> 又は第三者もしくは当社に不利益を与える行為。

> その他、当社が不適切と判断する行為。

**「本サービスの運営を妨害する行為」と「当社が不適切と判断する行為」に字面の線は無い。**
取得の速さと量は、robots.txt が無いから自由という意味ではなく、この 2 つに触れない側で決める (「レート間隔」)。

「営利を目的として」の号は**アフィリエイトで送客して報酬を得る形に当たりうる**。このストアのアフィリエイトプログラムは
見つかっていない (「未確認の項目」) ので、送客で収益を得る形にするなら、この号の扱いを先に運営元へ確かめる。
リンクを置くだけで報酬を伴わない形はこの号に当たらない。

**取得物の再掲は第 13 条 (著作権等の帰属) が制限している。**

> ② 利用者は、本サービスを提供するWEBサイト上に掲載、もしくは、本サービスを通じて提供される、
> いかなる画像データ、写真、映像、文章、音楽、音声、ソフトウェア等(以下総称して「データ」といいます)も、
> 以下に挙げるような著作権法で認められた私的利用の範囲を超える利用はできないものとします。
>
> データの一部といえども、それを複製し、第三者に配布・販売したり、出版、上映、放送、
> ウェブサイトへの掲載等のために使用すること
>
> データの一部といえども、それを編集・加工して前号の行為を行うこと

導けること: **説明文と画像の本体を自分の画面に載せない。** 載せてよいのは、
事実の記述にあたるタイトル・出演者名・発売日・レーベルと、ストアへのリンクまで。
カバー画像を出すなら、他ストアと同じく**配信元の URL を `<img src>` にそのまま渡す**形にして、
複製物を自分で配らない。カバー画像の URL のホストは **`api.stellaplayer.jp`** で、
「使ってはいけない URL」で「未調査」としているホストと同じである (2026-09-20 確認)。ここに載るのは画像だけで、
**取得するのは閲覧者のブラウザであって我々のクローラーではない**。クローラーからこのホストへ出す取得は
別の話なので、「使ってはいけない URL」の扱いは変わらない。

## レート間隔

**専用のキーを置かず、未知のホストに当たる既定値をそのまま使う。** 値は `crawler/lib/fetch.ts` の `rateLimitFor()`。

robots.txt が無く `Crawl-delay` の指定が無いので、何秒が妥当かは相手にしか分からない。
短くしてよい根拠 (robots の指定、公開されている API 枠) が 1 つも無いため、既定値より短くしない。
利用規約の包括条項 (「robots.txt」) も負荷をかけない側に倒す理由になる。

既定値で走ったときのスループットの実測は
[`docs/research/stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の
「調査方法とリクエスト実績」。全件 1 巡と日次のコストも同じ文書の「全商品を 1 巡するコスト」にある。

**UA は `userAgentFor()` の既定 (ブラウザ相当) のまま。** このホストが UA に何を求めるかは
公開されたものが見つかっていない (「未確認の項目」)。**既定のまま送った取得が、存在しないファイルの 404 以外
すべて HTTP 200 で返った**、というだけの根拠である。ステータスまで記録しているのは
[`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の「調査方法とリクエスト実績」。
[`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) の
同じ節は件数だけを記録している。

## 使ってはいけない URL

最終確認日 2026-09-20。

| 形 | 理由 |
|---|---|
| `api.stellaplayer.jp` の GraphQL | 禁止ではなく**未調査**。`/archive` の裏でブラウザが叩いている別ホストで、規約上の扱いも枠も確認していない。使う前に「robots.txt」と同じ手順でこのホストを調べ直す |
| `/archive` (`keyword` / `top_category` / `page` を付けた形) | 禁止ではなく**中身が入らない**。静的書き出しで `pageProps` が空。結果はクライアント側の取得で差し込まれる |
| `/` (トップ) | 同上。`pageProps` が空で、新着も載っていない |
| `/maker/[maker]` | 同上。`brand` の `id` を入れると HTTP 200 で `page` も `/maker/[maker]` に解決するが、静的書き出しで `pageProps` が空。**レーベルごとに商品を並べる安い 1 巡の経路にはならない** |
| `/ranking` | 同上。静的書き出しで `pageProps` が空。カテゴリトップに載る日次 / 週次ランキング以上のものは取れない |
| `/cart`、`/mypage/*` | 購入とアカウントの経路。取得する理由が無い |
| `/product/{id}` の HTTP ステータスで存在を判定する形 | **動くが誤る**。存在しない ID でも HTTP 200 が返る (「既知の落とし穴」) |

## 既知の落とし穴

いずれも 2026-09-20 の観測。

- **存在しない ID でも HTTP 200 が返る。** `product` が `null` になるだけで、
  ステータスコードもエラーページの語句も出ない。**`product === null` で判定する**
- **新着一覧に出演者が無い。** カテゴリ (`/general` `/bl` `/girls`) のトップに載る新着の各商品は
  `creators` を持たないので、一覧で対象声優を判定できない。新着の商品ページを 1 件ずつ引いてからでないと
  「対象声優が 1 人も出ていない作品は保存しない」
  ([`docs/product.md`](../product.md) の「対象作品」) を判定できない
- **新着一覧は 1 カテゴリ 10 件で、ページ送りの手段が HTML から見えない。** 1 ページ目が覆う期間は
  [`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の「新着一覧」
- **カテゴリトップの JSON はキーによって階層が違う。** `newProducts` / `preorderProducts` はオブジェクトで
  商品の配列は `.data` の下にあり、同じ位置の `dailyRanks` / `weeklyRanks` は素の配列である
- **sitemap も一覧 API も HTTP だけでは使えない。** 全件を舐めるなら `/product/{id}` を ID 1 から順に引くことになる。
  ただし [`decisions/0007`](../decisions/0007-daily-crawl-from-store-feeds.md) は「初期構築」の項で
  **全件取得はしない**と書いている。このストアで全件走査をするなら、その決定を置き換える決定が先に要る
- **`is_adult: true` の商品を 1 件も観測していない。** 引いた商品はすべて `false` で、
  その中には題名に性行為を書いた商品も、`調教` `寝取られ` のジャンルが付いた商品も含まれる。
  **`is_adult: false` を「全年齢」と読み替える根拠はこの観測から得られていない。**
  R18 が無いのか、フラグが内容の区分に対応していないのかを分ける材料も無い (「未確認の項目」)。
  観測した商品と題名は
  [`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) の
  「成人向け商品の見え方」
- **`__NEXT_DATA__` の script タグの属性がページによって違う。** 静的に書き出されたページ
  (`/maker/[maker]`、`/ranking`) には `crossorigin=""` が付き、サーバーで描くページには付かない。
  属性を決め打ちした正規表現で取り出すと、静的ページだけ「タグが無い」と誤る
- **対象声優に当たるかどうかが `top_category` と `category` の組で分かれる。** 「ドラマ」の商品では
  出演者の大半が対象声優に当たり、**GIRLS のシチュエーション**では 1 人も当たらなかった。
  GENERAL のシチュエーションは当たった例がある。カタログの大半は GIRLS のシチュエーションである。測定は
  [`docs/research/stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の
  「対象声優との重なり」と
  [`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) の
  「対象声優を含む商品の割合」
- **対象声優を含む商品は、ほとんどが既にポケットドラマ CD にもある。**
  [`docs/product.md`](../product.md) の「対象作品」はストア横断のマージをしないので、
  取り込むと同じ作品が別の行として並ぶ。件数は
  [`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) の
  「既存カタログとの重複」
- **`creators` には人名でない値が混じる。** `creator_group_id` が `"2"` の側に `ほか` が入っていた。
  出演者として使う `"1"` に混入するかは未確認 (「未確認の項目」)
- **`/archive` は HTTP 取得だけでは読めない。** 2026-09-18 の調査時点と 2026-09-20 で変わっていない。
  声優名での絞り込みも総件数もこの経路にある
- **声優のページが無い。** 声優から作品への導線はサイトに存在しない。
  このストアは声優起点で引けず、新着一覧と全件走査でしか作品を集められない
- **再生時間と役名が取れない。** `contents_size` は観測した全件で `null`、役名はタイトルと説明文の自由記述にしか無い
  ([`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) の「商品ページから取れる項目 / 取れない項目」)
- **1 つの作品が通常版・限定版・特典違いで別 ID に分かれる。** 束ねる手段はある。
  `editionGroup.activeEditions[]` に版ごとの `name` と `product.id` が入り、自分自身も含まれる。
  **珍しくない。**埋まり具合は
  [`stellaplayer-2026-09-20.md`](../research/stellaplayer-2026-09-20.md) と
  [`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) にある
- **`editionGroup` には版違いでないものも入る。** 同じシリーズの巻
  (`第1巻：…` `第2巻：…` `第3巻：…`) が `activeEditions[]` に並ぶ例がある。
  **`name` を見ずに束ねると別の作品を 1 つにしてしまう**
- **中身は HTML の DOM ではなく `__NEXT_DATA__` の JSON にある** (2026-09-20 観測)。新着と商品は
  `props.pageProps.dehydratedState.queries[0].state.data` の下にある
- **カテゴリは一覧の項目に無い** (2026-09-20 観測)。どのカテゴリトップ (`/general` `/bl` `/girls`) から
  来たかで代用するしかない
- **商品ページの正規 URL は `https://www.stellaplayer.jp/product/{id}` で、クエリパラメータが要らない**
  (2026-09-20 観測)

## 未確認の項目

実装を始めるときに分かれば足りるもの。

- **`sale_status` の全語彙。** 販売終了を表す値があるか。観測は `ON_SALE` と `PREORDER` の 2 つだけ
  ([`decisions/0008`](../decisions/0008-no-price-no-availability.md) の取り下げ判定に要る)
- **`creator_group_id` の全語彙**と、`"1"` に人名でない値が入りうるか
- **`product` が `null` になる理由。** 欠番・非公開・削除を区別する材料が無い
- **`editionGroup.activeEditions[]` の `name` の語彙。** 版違い (`通常` / `ステラワース限定` /
  `特典…付`) と巻 (`第1巻：…`) の両方が入ることは観測したが、区別できる規則があるかは分かっていない
- **新着一覧を 10 件より多く取れるか。** サーバー側の問い合わせは引数が固定で、
  ページ送りの手段が HTML からは見えない
- **商品の総数の確定値。** 標本からの推定しか無い
  ([`stellaplayer-coverage-2026-09-20.md`](../research/stellaplayer-coverage-2026-09-20.md) の
  「商品の総数」)。ID を 1 から順に引く全件 1 巡の規模がこの値で決まる。
  総数を返す経路は `/archive` の裏の別ホストにしか無く、そのホストは未調査 (「使ってはいけない URL」)

取得を始める前に確かめるもの。

- **`is_adult: true` の商品がこのホストにあるか。** 引いた範囲はすべて `false` で、
  フラグが何を表しているのかを確かめる材料が無い (「既知の落とし穴」)。年齢確認の導線も見つかっていない。
  R18 を載せない ([`decisions/0003`](../decisions/0003-no-r18-keep-bl.md)) ので、
  **取り込むなら「このストアの商品から R18 を除ける」と言える根拠を先に作る。**
  年齢区分を `unknown` で保存するだけでは、0003 の「読み取り側は R18 だけを除く」が
  何も除かないことになる
- **UA の要求。** このホストが何を求めるかを書いたものは見つかっていない。既定のブラウザ相当で
  通った実績があるだけである (「レート間隔」)
- **アフィリエイトプログラム。** このホストの取得物には見当たらなかった。
  「robots.txt」の利用規約の「営利を目的として本サービスを利用する行為」の号の扱いも、あわせて確かめる必要がある
- **JS の実行が要る経路。** `/archive` の絞り込みと総件数、声優名での検索。
  この調査ではブラウザを立ち上げていない
